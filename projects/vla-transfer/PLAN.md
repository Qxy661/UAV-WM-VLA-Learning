# 跨载体 VLA 迁移：方案（执行前定稿）

写于 2026-10-25。这份文件在执行前定稿，跑的过程中只允许改「阶段状态」，不允许改假设与判据。
理由：事后调整判据的实验没有信息量。

## 1 要回答的三个问题

- **Q1 迁移**：预训练 VLA（π0.5）的动作头从 7 维机械臂迁到 4 维推力加角速率，还剩多少能力？和同样数据从头训的行为克隆比，预训练到底带来了什么？
- **Q2 归因**：如果迁移不成功，多少来自视觉域差（仿真 96² vs 预训练真机）、多少来自动作空间重构、多少来自指令分布？
- **Q3 可比性**：同一套评测协议能不能同时承载「无人机巡检」和「LIBERO 机械臂」两种载体，并且数字对外可比？

## 2 不做什么

- 不刷分：不为了逼近 96.85 改评测协议；协议与官方不同就在 `metrics.json` 里标出来
- 不做真机：没有硬件，所有结论限定在仿真
- 不造第三个载体：轮式机器人没有现成、有外部基准的仿真，自己写一个就是新的玩具，只做接口预留
- 不并行占卡：一张 4090，训练与评测串行

## 3 三条线

| 线 | 内容 | 目的 | 依赖 |
|---|---|---|---|
| T1 UAV | π0.5 LoRA 适配仓储巡检，`action_dim=4` | 独特性：别人没有的跨载体适配 | P0 环境 + P1 数据 |
| T2 锚点 | LIBERO 上 π0.5-LIBERO 复现一个数字 | 可比性：和公认 benchmark 对齐 | P0 环境 |
| T3 对照 | 机械臂上 OpenVLA 与 π0.5 同 harness 对比 | 架构对照：离散动作头 vs 流匹配头 | T2 完成 |

T1 先做，因为它决定后面两条线值不值得做。T2 是 T1 的外部锚点，T3 只在 T2 顺利时启动。

## 4 统一接口（三条线共用）

```python
class Embodiment(Protocol):
    name: str
    obs_spec: dict          # 图像键、分辨率、状态维度
    action_spec: dict       # 维度、范围、频率、是否分块
    instruction_space: list # 指令模板与槽位

    def build(self, seed: int) -> Task: ...
    def expert(self, task: Task) -> Trajectory: ...   # 生成数据用
    def score(self, traj: Trajectory, task: Task) -> dict: ...
```

评测侧沿用 M6 已有的 `TaskSpec` / `run_episode` / `evaluate` / `compare`，新增的只是 `Embodiment` 注册表。
`compare()` 遇到不同 `protocol.version` 会抛错，这条已经实现并有测试。

三个实现：`UAVInspection`（已有仿真）、`LIBEROArm`（robosuite）、`OpenVLAArm`（复用 LIBEROArm 的观测与动作，只换策略）。

## 5 实验设计（预注册）

### 5.1 基线，缺一不可

| 基线 | 作用 | 如果缺了会怎样 |
|---|---|---|
| scripted 专家 | 上界 | 不知道任务本身有多难 |
| hover-only | 下界 | 不知道「什么都不做」多少分 |
| random | 下界 | 不知道 harness 能否区分 |
| **行为克隆（BC）** | **判断预训练是否带来迁移** | 会把「数据教会了模型」误读成「预训练有用」 |

BC 基线规格：同一批数据、同一视觉输入、CNN + MLP 约 2M 参数、同样 30k 步、同 chunk 长度。
**这条是整个方案的地基**：如果 π0 不比 BC 高 10 个点，结论必须写成「预训练未带来可测迁移」。

### 5.2 三档消融

| 编号 | 训练什么 | 可训练参数 | 回答什么 |
|---|---|---|---|
| A1 | 只换 4 维动作头，骨干全冻 | < 5M | 现有表征够不够用 |
| A2 | 动作头 + 视觉编码器 LoRA | 约 20M | 视觉域差是否是瓶颈 |
| A3 | 全层 LoRA | 约 60M | 上限 |

### 5.3 假设与判据

| 假设 | 判据（写死） | 若判据不成立说明 |
|---|---|---|
| H1 预训练有迁移 | A3 在 held-out 指令组合上比 BC 高 ≥ 10 个百分点 | 预训练没带来可测迁移，项目降级为方法演示 |
| H2 动作头不能直接复用 | A1 比 BC 低 ≥ 10 个百分点 | 动作头可从机械臂直接迁，结论反转为正向 |
| H3 瓶颈在视觉 | A2 与 A3 差距 < 5 个百分点 | 瓶颈在语言或动作层，需改消融设计 |

### 5.4 held-out 指令组合

指令由槽位生成：`{货架 1–4} × {视点 front / oblique} × {动作 拍目标 / 巡检}`。
训练集只放部分组合，测试集只放**没见过的组合**。这是 VLA 该考的东西：不是复现训练过的指令，是对新组合的泛化。

### 5.5 统计

- 每策略 200 回合（20 任务 × 10 回合），配对种子（同一 seed 下所有策略跑同一个场景实例）
- 成功率给 95% bootstrap 区间（按回合重采样）
- 分辨率 1/200，比 60 集时细三倍；差距小于 5 个点的结论一律写「不显著」

## 6 数据规格

| 项 | 取值 | 理由 |
|---|---|---|
| 分辨率 | 96×96 | 比 M2 的 64² 少一点域差，体积仍可控（约 24 GB） |
| 帧率 | 采集 9.6 Hz，动作块 8 步 | 与 M3 世界模型一致，chunk 覆盖约 0.8 s |
| 规模 | 8000 集（train 6400 / val 800 / test 800） | 单卡一晚能过 3 遍 |
| 指令 | 槽位模板，约 40 种表述 | 表述多样性与组合留出 |
| 划分 | 按 episode，且测试集的指令组合与场景 seed 双留出 | 防泄漏，见 `docs/10-横切判据/06-数据泄漏与划分.md` |
| 存储 | `obs.npz + meta.json + manifest.json` | 与 M2 一致；不用 parquet/mp4 是因为本机装不上 torchcodec |
| 生成位置 | 开发机本地生成，不外传 | 纯 CPU，约 3–5 小时 |

### P4 的判据修正（2026-10-25）

`eval_uav.py` 原来沿用数据生成器的"到达"口径（离视点 0.16 m），与 M6 harness 的
"拍摄"口径（0.7 m 内 + 目标在视场 + 无遮挡）不是一回事。同一批 20 条轨迹两套口径
给出 0/20 与 4/20。判据现已收敛到 `projects/vla-transfer/eval/protocol.py` 一份实现，
`eval_uav.py`、`recount_coverage.py` 都调它；历史数字在 `RESULTS.md` 附录里标注了口径。


## 8 风险与止损

| 风险 | 触发信号 | 处理 |
|---|---|---|
| 服务打不通 | P0 超过 48 小时 | 停，改用离线批量推理脚本 |
| 数据不能收敛 | BC 在 test 上 < 20% | 停，先修任务难度或数据量，不碰 π0 |
| 显存不够 | A3 的峰值 > 24 GB | 降 batch、开梯度检查点，仍不行改 A2 为主结论 |
| 迁移无效果 | H1 判据不成立 | 不改判据；把结论写成负结果，项目定位改为「跨载体适配与评测方法」 |
| LIBERO 装不上 | P6 超过 2 天 | 放弃 T2，接受缺少外部锚点，并在文档里写明 |
| 时间超支 | 总进度超过 15 个工作日 | 砍 T3，保留 T1 与 T2 |

## 10 可以宣称「有效」的条件

同时满足三条，才允许在 README 写「预训练带来迁移」：

1. A3 在 held-out 指令组合上比 BC 高 ≥ 10 个百分点，且 95% 区间不重叠
2. scripted 上界 ≥ 90%，说明任务本身可解
3. 消融能指出瓶颈所在（视觉 / 动作 / 语言），不是「调参调出来的」

任何一条不满足，README 上的表述必须写成「搭好了跨载体适配与评测链路，迁移效果不显著，原因如下」。
