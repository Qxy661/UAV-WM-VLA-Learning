# 训练协议

这份协议是为了让表里的数字能被别人复核，而不是为了让数字好看。所有报告过的闭环结果都必须由 `run_protocol.sh` 产出。

## 六条硬规则

1. **划分按 episode，不按帧**。同一段轨迹的相邻帧只差 33 ms，按帧随机划分等于把训练集复制进验证集。划分由 `uavinspect/data/instructions.py:split_of(seed)` 决定：train 0–6399、val 6400–7199、test 7200–7999。
2. **测试集只碰一次**。调参、选点、早停全部看 val；test 只用来出最终表格。任何"看了 test 再改"的迭代都让 test 失效。
3. **选点按验证集**，`best_epoch` 由 `val_err_cm` 最低的那轮决定，而不是最后一轮。训练日志里同时记 `train_*` 与 `val_*`，两条曲线的分歧本身就是信息。
4. **种子固定且报告**。`--seed` 同时固定 torch / numpy / DataLoader 的洗牌顺序。一条结论至少要三个种子，报 mean±std；单一 seed 的数字只能用来发现方向，不能用来排名。
5. **失败样本计入分母**。超时、坠机、越界都算失败，不能剔除。覆盖率过滤只作用于训练集（专家没走完的轨迹没法当示范），评测集一条都不删。
6. **口径单一实现**。判据只写在 `vla-transfer/eval/protocol.py` 里，训练、评测、离线复算都调它。三处各写一遍是这类项目最常见的自欺方式——`docs/04` 记了四次实例。

## 超参基线

| 项 | 值 | 理由 |
|---|---|---|
| 优化器 | AdamW, wd=1e-4 | 与 BC 基线一致，避免两套配置无法比较 |
| 学习率 | 5e-4（子目标）/ 1e-3（BC），余弦退火 | 前期快、后期稳；不做 warmup，因为 batch 256 已经够稳 |
| batch | 256 | 8 GB 显存下能跑满，再大收益不抵时间 |
| epoch | 40（子目标）/ 6（BC） | 由验证曲线拐点决定；早停 `patience=6` 兜底 |
| 动作块 horizon | 8 | chunk 太短等于每步重规划，太长则跟踪误差吃掉精度 |
| 抽帧 stride | 2（子目标）/ 2（BC） | 9.6 Hz 下相邻帧几乎相同，不抽等于重复采样 |

## 一次完整跑法

```bash
bash projects/vla-transfer/scripts/run_protocol.sh \
  --data /root/work/data/uav96c2 --ckpt-kind subgoal --seeds "0 1 2" --epochs 40
python projects/vla-transfer/scripts/summarize_protocol.py --runs runs/sgp_s0 runs/sgp_s1 runs/sgp_s2
```

`run_protocol.sh` 每个种子做两件事：训练（选点看 val）→ 评测 60 集（test，判据 m6-v1）。评测输出里的 `metrics.json` 带逐回合 `rows`，可以直接喂给配对检验。

## 报告格式

主表一行一个策略，列固定为：`success ± std（跨种子）`、`95% Wilson（合并回合）`、`n`、`min|u| 中位`。跨种子 std 与合并 Wilson 是两件事：前者衡量训练随机性，后者衡量评测样本量，不能互相替代。

配对检验按种子各做一次，但**不要把三个 p 值里最小的那个当结论**——那等于用三次机会换一个显著。写法是：取点估计最强的那个种子作为主张，其余种子只作为重复性证据，并在表注里写明另外两个种子有没有符号一致。

## 不做什么

- 不扫学习率找最好的那个再报（那是拿 test 调参的变体）
- 不在训练集上报告指标
- 不用"平均奖励"代替成功率——奖励是连续的，成功率是判据，两者不可换算
