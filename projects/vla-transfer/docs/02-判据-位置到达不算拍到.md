# 判据：位置到达不算拍到

`projects/vla-transfer/RESULTS.md` 里所有成功率都出自同一个函数：
`eval/protocol.py` 的 `m6_coverage()`。这份文档解释它为什么长这样，
以及前面两版判据各自错在哪。

## 第一版：离视点 0.16 m 算到达

数据生成器用这个口径：机体系位置与目标视点的欧氏距离小于 `WP_TOL = 0.16 m`
就算到过。它服务的是"专家能不能飞完路线"，不是"有没有拍到东西"。

用它评策略会同时高估和低估：

- 高估：飞到了视点但机头朝墙，画面里什么都没有，照样计成功。
- 低估：在 0.3 m 外就把目标拍满画面，但因为没进 0.16 m 被判失败。

同一批 20 条轨迹，第一版判 0/20，换成拍摄口径后是 4/20。差异不是噪声，
是判据在量不同的东西。

## 第二版：0.7 m + 目标在视场 + 无遮挡

这是评测 harness 的口径，三个条件同时满足才算拍到：

```
距离 <= 0.7 m
目标在水平视场内（70°）
机体到目标的射线不被货架挡住
```

它修掉了朝向问题，但仍然留了一个洞：**朝向是"应该朝哪"还是"实际朝哪"**。

第一版实现里，数据生成器渲染和覆盖判定都用指令朝向 `yaw_wp`，
等于假设机载相机是完美云台，永远正对目标。真实情况是相机固连机体，
机体不转，画面就不动。用 `yaw_wp` 判覆盖，会让"从不转向"的策略白拿覆盖。

改成用实际姿态 `st.yaw` 之后，还剩下第二个洞，它更隐蔽：

**指令里已经写了去几号货架、从哪一侧拍。** 目标位置因此由状态与提示词
唯一确定——策略不需要看图像，只要按指令飞到对应位置，几何上就满足了
"在视场、无遮挡"。实测也证实了：把训练图像全部置零（`--blind`）的策略，
60 集成功率 0.250，能看见的是 0.200，区间重叠。图像与指令都没有进入决策，
20–25% 来自"残差动作空间 + 高度前馈"这条状态机式的轨迹。

## 第三版：让位置推不出像素

两个改动同时做，缺一个都不成立。

**一、目标在货架面内抖动。** 目标不再固定在货架中心，`dx ∈ ±0.40 m`、
`dz ∈ ±0.20 m`，由 seed 散列成连续值（三档离散值会让约三分之一的 seed
恰好 `dx = 0`，盲策略正对货架就白捡）。

**二、成功要求标记落在画面中心附近。** 水平归一化坐标 `|u| <= 0.12`，
其中 `u = (d · right) / (d · fwd) / tan(hfov/2)`。不判竖向：视点高度锚在
货架中心 1.05 m，目标 z 抖 ±0.2 m，竖向偏移恒约 −0.42，判 v 会让专家也过不了。

关键的一点：**视点位置锚在货架中心，只有视点朝向指向目标真实位置。**
如果视点位置也跟着目标抖，"该飞哪"就变成了答案的一部分，任务退化成盲搜，
专家示范也不可复现。现在分工是：位置由指令决定，朝向只有看过图像才知道。

## 区分度实测（seed 7200–7205）

悬停段（`10 <= phase < 20`）的最小 `|u|`：

| | 7200 | 7201 | 7202 | 7203 | 7204 | 7205 |
|---|---|---|---|---|---|---|
| 专家（朝向指向目标） | 0.024 | 0.018 | 0.001 | 0.002 | 0.025 | 0.019 |
| 盲（朝向固定正对货架） | 0.000 | 1.181 | 0.151 | 2.191 | 0.052 | 1.370 |

盲策略 2/6 蒙中，都是 `|dx| < 6 cm` 的 seed。这是预期的区分度，不是漏洞：
抖动幅度与视场角共同决定"运气窗口"有多宽。要让它更窄，只能加大抖动或缩视场，
两者都有代价——抖动太大会让专家也拍不到，视场太小会削弱可用观测量。

## 这个判据不能证明什么

- 不能证明策略"理解了目标是什么"。它只要求把红色标记推到画面中心，
  蓝色干扰标记在另一排，永远不在目标货架制造歧义。真要测语义，
  得让干扰与目标同排、同深度，且指令只给颜色以外的属性。
- 不能证明策略具备搜索能力。当前任务里目标货架由指令给定，
  策略不需要"先找再拍"。搜索能力要另一套任务：指令不给货架号。
- 0.12 这个阈值是几何推导 + 六条轨迹自检定的，不是标定出来的最优值。
