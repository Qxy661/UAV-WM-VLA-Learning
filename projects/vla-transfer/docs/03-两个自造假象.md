# 03 两个我自己造出来的假象

这两件事都不是模型的问题，是**评测代码的问题**。它们的共同点是：结果看上去像一个
干净的结论（一个是"策略彻底失效"，一个是"策略从没对准过"），但两句话都不成立。
写下来是因为它们比任何一次成功都更值得复述——同样的错在任何具身项目里都会再犯一次。

## 假象一：四格全 0，看起来像"改动把策略弄坏了"

改完判据（居中 + 抖动）后第一次跑四格评测，四个格子全部 `success = 0.000`。
当时的反应是"新判据太严，或者新数据有问题"。

真实原因是链式脚本里评测命令漏了一个参数：

```bash
# 训练时
train_bc.py --residual ...
# 评测时（错的）
eval_uav.py --ckpt runs/bc_c/ckpt.pt --data ... --episodes 60 --device cuda
```

`--residual` 的意思是"网络输出的是相对悬停基准的残差"。评测不带这个参数，
`ChunkPolicy` 就按绝对动作去解释同一个 ckpt，输出的推力被当成 0–21 N 的绝对值，
力矩被当成 ±0.5 N·m 的绝对值——于是每一拍都在往地面或天上怼。飞行器还在飞，
只是完全不受控，`success` 自然是 0。

**为什么它骗过了我**：0/60 是一个"干净"的数字，而且方向符合预期（判据更严 → 更难成功）。
预期与结果一致时，人不会去查参数。

**怎么防**：`ckpt.pt` 里已经存了 `args`（`train_bc.py` 一直这么写）。评测脚本应当在
加载时比对 `args.residual`、`args.horizon` 与自己命令行是否一致，不一致直接报错退出。
这一条已写进 `STATUS.md` 的队列；当前是手工核对。

## 假象二：`min|u|` 全程取最小，奖励"飞得远"

为了在成功率之外看一个连续量，我加了 `min_abs_u`：整段轨迹里目标在画面中的
最小水平偏移，越小说明越"对准"。第一版是全程取最小，结果四格里半数回合的
`min|u|` 只有 0.1 左右——看起来"早就对准了，只是判据没过"。

几何上这是错的。视场 70°，目标横向偏移 `dx` 在距离 `d` 处对应的归一化坐标是

```
u = (dx / d) / tan(35°)
```

`dx = 0.40 m`、`d = 0.7 m` → `u ≈ 0.57`；同样 `dx = 0.40 m`、`d = 5 m` → `u ≈ 0.08`。
**离得越远，同一个横向偏移看起来越"居中"**。于是"停在远处不动"反而是这个指标的
最优策略，它测的是距离，不是对准。

**修法**：只在距目标 ≤ 0.7 m 的步上取最小值；若整段没有一步进到 0.7 m 内，
返回哨兵值 `9.0`。

**修完之后的读数**：四格的中位 `min|u|` 全部是 `9.000`。也就是说，过半回合根本
没飞到位——瓶颈从"感知"变成了"路线复现"。这个结论比修之前那个假象有用得多，
因为它指向的动作是"补复位示范"，而不是"加视觉模块"。

## 两条可以带走的规则

1. **连续量必须先问"它的最优策略是什么"**。如果最优策略是"什么都不做"或者
   "离得远远的"，这个量就测不到你想测的东西。取最小/最大/末值之前，先写出这个
   量在极端输入下的值。
2. **参数不一致要用代码拦，不要用眼睛拦**。`--residual`、`--blind`、`--horizon`
   这类"训练和评测必须一致"的开关，靠人核对一定会漏一次；漏的那次恰好会给出
   一个方向正确的错结论。
