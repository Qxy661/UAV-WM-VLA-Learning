# uav-inspect —— 多机协同巡检（可运行工程层）

> 主库 `docs/` 是**知识层**（讲原理、判据、边界）；本项目是**工程层**（讲取舍、契约、退化）。
> 两者用知识点编号（KP）缝合：本项目每一节末尾的 `KP:` 指向主库对应章节。

## 1. 这个系统要回答什么问题

一句指令，三架无人机在带遮挡的园区里完成巡检：

> "去 3 号楼西侧，沿围墙跟住那辆白色货车，别撞电线杆。"

系统需要自主决定：**谁去**（多机分配）、**怎么去**（规划与避让）、**看不到时怎么办**（世界模型补全）、**听懂话**（VLA 指令跟随）、**坏了怎么办**（安全层一票否决）、**凭什么说它好**（统一口径评测）、**能不能上机**（量化 + 延迟 P99）。

## 2. 与"玩具 demo"的区别（明确取舍）

主库 `code/` 下 24 个 demo 的定位是**认知验证**：单文件、纯 CPU、合成数据，用来把一个概念的可解析结论算出来。它们**不承担**工程职责，也不声称有外部效度。

本项目承担工程职责，因此必须满足以下四条硬约束：

| 约束 | 具体做法 | 反例（主库 demo 的问题） |
|---|---|---|
| 参数可配 | 全部进 YAML，加载时校验范围 | 模块级常量 `OMEGA_MAX = 5.0` 不可覆盖 |
| 频率分离 | 物理 240 / 控制 48 / 策略 10 / 相机 5 Hz | 单层 `for step in range(N)` 混在一起 |
| 结论可生成 | 指标由代码统计写入 `metrics.json`，禁止手写 | `print("超过其 2024 全年产出")` 写死 |
| 有第二个使用者 | 模型、控制器、评测器都被脚本与测试共用 | 每个 demo 自己实现一套 |

## 3. 架构

```
                 ┌──────────────────────────────┐
   语言指令 ────▶ │ instruction parser (M4)      │
                 └──────────────┬───────────────┘
                                ▼
   ┌──────────┐   ┌──────────┐   ┌──────────┐   ┌──────────┐
   │ perceive │──▶│  world   │──▶│  policy  │──▶│  safety  │──▶ 控制桥 ──▶ 物理
   │ (M2)     │   │ model(M3)│   │ (M4)     │   │ (M5)     │     48 Hz      240 Hz
   └──────────┘   └──────────┘   └──────────┘   └──────────┘
        ▲               ▲              ▲              │
        └───────────────┴──────────────┴──────────────┘
                    eval harness (M6) / deploy (M7)
```

频率为什么这样分：物理 240 Hz 对应 PX4 内环；控制 48 Hz 对应 Offboard 设定点流；策略 10 Hz 是 VLA 单次推理的现实上限（大模型 3–10 Hz）；相机 5 Hz 是机载算力下的保守值。**VLA 不能 50 Hz 直连**，所以策略输出的是 **action chunk**（一次出 K 步），由控制桥插值跟踪。

## 6. 运行

```bash
# 本机（Windows，Python 3.9 里已有 numpy / pyyaml / torch）
py -3.9 projects/uav-inspect/scripts/m0_hover.py --backend rigid

# 只想要 pybullet 后端（需要该解释器装得上 pybullet）
py -3.9 -m pip install pybullet
py -3.9 projects/uav-inspect/scripts/m0_hover.py --backend pybullet

# 契约测试（需要 pytest；CI 里跑）
py -3.9 -m pytest projects/uav-inspect/tests -q

# M2：录 8 集巡检数据（rigid 后端约 20 s 跑完）
py -3.9 projects/uav-inspect/scripts/m2_inspect.py --episodes 8 --backend rigid
```

`--backend auto`（默认）表示"导得进 pybullet 就用它，否则用自研积分"，实际选了哪个会写进
`metrics.json` 的 `sim.backend` 和 `env.json` 的 `deps.pybullet`。产物在
`projects/uav-inspect/runs/m0_hover/`：`metrics.json`（指标）、`env.json`（环境指纹）、
`trace.csv`（逐帧轨迹）。

M2 的产物在 `runs/m2_dataset/`：每集一个目录（`obs.npz` 存图像/位姿/动作/相位，`meta.json`
存覆盖率与被挡视点），外加 `manifest.json`（划分）与 `stats.json`（**只用 train 划分**算的
归一化参数——用 val 算统计量是最常见的一种泄漏）。

## 7. ADR（架构决策记录）

- **ADR-001** 用 PyBullet 而非自研点质量模型：需要真实转动惯量、接触、传感器渲染。自研模型（`code/common/quad_sim.py`）把姿态当无惯量的直通量，无法承载控制、避让、接触三类实验。代价：CPU 每步 ~0.2 ms，3–4 机仍在预算内。
- **ADR-002** 不自带 URDF 资产，用程序化 body + 二次桨叶力模型：避免资产与版本漂移（`gym-pybullet-drones` 已迁移仓库、URDF 路径多变）。差异与校准项记在 `docs/adr/002-rotor-model.md`，不假装等价。
- **ADR-003** 四层频率分离：见 §3。
- **ADR-004** 控制用串级 PID + 姿态环，不用开环角速率：开环角速率在真实动力学下会自激，这是主库 demo 里被注释承认的问题。
- **ADR-005** 延迟只报 P50/P99，不报均值：均值会掩盖尾部，部署看的是 P99。
- **ADR-006** 配置集中 + 范围校验：坏配置在加载时就失败，不在第 800 步产生 NaN。
- **ADR-007** 每个 episode 显式 seed，环境指纹随结果落盘：没有指纹的结果不可复现，不可比较。
- **ADR-008** 双后端（`rigid` / `pybullet`），默认自动选：混控、电机滞后、悬停反解抽到
  `sim/dynamics.py` 共用，只有"力怎么变加速度"这一段分叉——`rigid` 用 RK4 + 冲量式接触（仅 numpy），
  `pybullet` 交给引擎。理由是 ADR-001 的前提在有些机器上不成立（cp311 没有 pybullet 的 Windows
  wheel），“跑不起来”不该和“仿真不可信”混成一件事。代价：两个后端会给出不同数字，
  所以 `metrics.json` 必须记 `sim.backend`，且 M0 的验收阈值按更保守的那个定（RMSE 0.20 m，
  实测 rigid 0.0117 m、pybullet 待补）。rigid 后端已知不真实：接触只作用在质心（撞墙后姿态不会被打歪）、
  没有摩擦锥、机体之间是刚性球。
- **ADR-009** 避让用互惠斥力 + 单向让步，不用 ORCA：ORCA 要解每个体的允许速度半平面交集，
  调参成本高，而 M1 只验一条更弱更硬的命题（四机交叉时任意两机不低于 0.6 m）。
  代价是它不是完备的（凹形地形会卡住），所以 M1 只放两根柱子。
  **调参记录（这是本 ADR 的重点）**：最初 `d_influence=1.5 m, k_rep=1.2, v_avoid=1.6` 时四机最近掉到
  **0.280 m**——原因是 1.6 m/s 的接近速度下，从 1.5 m 才开始躲，需要约 7 m/s² 的横向加速度，
  而 30° 倾角只给得出 5.7 m/s²，物理上来不及。把影响半径放到 2.5 m、巡航降到 1.2 m/s 后
  最小间距 1.165 m。结论：**这类避让的通过与否主要由"提前量"决定，不是由斥力增益决定**。
  同一批设置下只加增益的对照（影响半径保持 1.5 m）：`k_rep=2.0` → 0.493 m、`k_rep=4.0` → 0.537 m，
  都不达标；而把影响半径放到 2.0 m（`k_rep=1.5`）就到 0.824 m，2.5 m 才到 1.165 m。
- **ADR-010** 数据用 `obs.npz + manifest.json + stats.json`，不直接落 LeRobot 格式：
  LeRobot 的 parquet + mp4 需要 `datasets`/`torchcodec` 依赖，本机装不上，而 M2 只需要
  "能训练、能划分、能复现"三件事。语义上照抄它的两条规矩——**划分按 episode 不按帧**、
  **归一化统计只用 train**；`manifest.json` 里保留 `split` 字段，将来要换格式时按目录搬即可。
  相机是解析式针孔（射线求交 + 两盏灯的兰伯特着色），不依赖渲染后端；已知不真实：没有材质、
  没有阴影、没有运动模糊，遮挡只由几何决定。巡检目标给了 0.55 的自发光比例，因为仓库通道侧
  立面永远背光，纯兰伯特下红灯渲染出来接近黑色，世界模型什么也学不到——这是有意的可视化取舍，
  不是"真实外观"。

## 8. 非目标（明确不做）

- 不追求 SITL/真机联调（PX4、ROS2）——只留接口与文档说明，理由见 ADR-001 与主库 P7 卷。
- 不追求比论文更好的指标；目标是**同口径下能横比**。
- 不实现真实建图（多地面轮式建图是后续方向），但 `Agent(obs) -> action` 接口与 `sim/` 的载体抽象为此留位。
