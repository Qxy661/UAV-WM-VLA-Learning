# 08 怎么用这个系统

## 五条命令

```bash
# 0. 只用 numpy，不需要 GPU、不需要 pybullet
py -3.9 projects/uav-inspect/scripts/m0_hover.py --backend rigid

# 1. 四机交叉，看间距
py -3.9 projects/uav-inspect/scripts/m1_multi.py --backend rigid

# 2. 巡检并录数据（8 集，约 20 s）
py -3.9 projects/uav-inspect/scripts/m2_inspect.py --episodes 8 --backend rigid

# 3. 安全层四类故障
py -3.9 projects/uav-inspect/scripts/m5_faults.py

# 4. 三基线同口径评测（全量约 3 分钟）
py -3.9 projects/uav-inspect/scripts/m6_eval.py --episodes 20 --seeds 3
```

每条命令都做三件事：跑仿真、写 `runs/<里程碑>/`、按声明过的条件打"通过/未通过"。
判定条件写在脚本里，不写在文档里，改阈值必须改代码，改代码会被 review 看到。

## 产物在哪，看什么

| 路径 | 内容 | 先看哪个字段 |
|---|---|---|
| `runs/m0_hover/metrics.json` | 悬停 RMSE、倾角、四阶段延迟 | `checks.rmse_ok`、`latency.physics` 的 P99 |
| `runs/m1_multi/metrics.json` | 最小间距、冲突步数、末态误差 | `min_separation_m` |
| `runs/m2_inspect/manifest.json` | 集数、划分、每集帧数与覆盖率 | `episodes[].coverage` |
| `runs/m3_wm/metrics.json` | 重建/开环误差、可见性 AUC、三个基线 | `passed` 与 `vis_pos_rate` |
| `runs/m5_faults/metrics.json` | 四类故障的最高挡位与回稳误差 | `checks.recovered` |
| `runs/m6_eval/metrics.json` | 三基线的成功率、覆盖率、间距、用时 | `protocol` 与各自的 `ci95` |

`env.json` 记命令行、cwd、git commit、平台、配置哈希。复现问题时先比这五项：
数字对不上时，一半的情况是配置或 commit 不同，"我这边跑不出来"通常不是玄学。

## 改参数的顺序

1. **先改 `configs/default.yaml`**，不要把常数写进脚本。加载时有范围校验，
   越界的值会 `ConfigError`。
2. **改控制参数后重跑 M0 再跑别的**。`pos_kp` 从 1.0 调到 2.0 会让悬停更快收敛，
   但也更容易在 M1 的交叉场景里超调。M0 是最便宜的回归测试。
3. **改场景后重跑 M2，再重训 M3**。数据是训练输入，`manifest.json` 里的哈希会变，
   `stats.json` 也会变。不同数据训出来的指标不能直接比。
4. **改 `TaskSpec` 的默认值等于换一把尺子**。M6 的 `compare()` 会拒绝跨口径比较，
   历史数字需要重新标注版本。

## 五个已经踩过的坑（省你一轮）

| 现象 | 原因 | 正确做法 |
|---|---|---|
| 可见性 AUC 恒 0.500 | 红色像素阈值写成 `0.6*255`，图像已归一化 | 阈值统一在 `[0,1]`，并打印正例占比 |
| 四集数据里三集一样 | `rng.integers` 选槽位，小 seed 撞车 | 用 `seed % 槽数` |
| 机体刚起飞就擦墙 | 斜前视点被墙夹在 0.36 m 内 | 视点按可达空间收边 |
| 偏航一转机体就飞出去 | 一步转 90°，姿态环吃到 1.5 rad 误差 | 偏航限速 0.8 rad/s |
| 推力裁剪检查恒为真 | 拿牛顿量纲和 1.0 比 | 对着 `thrust_abs_max` 比 |

这五条的共同结构：**没有报错，只是某个结论悄悄失效**。系统层的价值一半在这里。

  然后在 `m6_eval.py` 的 `makers` 里加一行。别改 harness。

  （cp311 wheel 齐全，Apache-2.0）。
