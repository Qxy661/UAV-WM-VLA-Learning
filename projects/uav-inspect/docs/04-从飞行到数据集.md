# 04 从飞行到数据集：录制、划分与两个静默坑

## 录什么

`uavinspect/data/recorder.py` 的 `EpisodeRecorder` 每次 `add()` 存一行：
`pos`、`vel`、`quat`、`action`（推力 + 三轴力矩）、绝对时间 `t`、阶段码 `phase`，
以及可选的 `image`。`close(meta)` 落成 `obs.npz` 加 `meta.json`。

三个设计决定：

- **绝对时间，不存帧号**。相机 5 Hz、控制 48 Hz，只要出现两个频率就一定会有人按索引
  对齐（M2 的第一版就踩了：1105 个 step 对 115 张图，布尔索引直接 `IndexError`）。
  所以下游一律按 `frame_t` 找最近的 step。
- **阶段码而不是分段表**。`0` 起飞、`1+wi` 接近第 wi 个视点、`10+wi` 悬停、
  `20` 返航。要统计"接近段耗时"时不用再解析轨迹。
- **划分按 episode，不按帧**。相邻帧只差 100 ms，按帧随机划分等于把测试集混进训练集。
  `write_manifest(out_dir, episodes, val_every=3)` 按 seed 排序后每 3 个取 1 个进 val。

`compute_stats()` 只在 train 划分上算 mean/std/min/max，写进 `stats.json`。
这条和 LeRobot 的规矩一致：归一化统计用到了 val 的分布，就等于提前看了答案。

## 相机为什么是解析式的

`uavinspect/sim/camera.py` 是一个针孔相机加射线求交，没有渲染管线：

- `rays(yaw, pitch, w, h, hfov)` 生成世界系单位方向；
- `raycast()` 用地面平面 + 轴对齐盒的 slab 法求交点，`box_id = -1` 是地面、`-2` 是天空；
- `shade()` 两盏灯（顶灯 + `-y` 补光）+ 距离雾化。

两盏灯是必需的，不是调色。仓库通道侧的立面永远背光，纯兰伯特下贴在货架上的红色目标
渲染出来接近黑色，`red_fraction` 统计到 0 个红像素，世界模型什么也学不到。加一盏
从通道侧打过来的补光、再给目标 0.55 的自发光，front 视点才有 100 个左右的红像素。

已知不真实：没有材质、没有阴影、没有运动模糊，遮挡只由几何决定。写进 ADR-010。

## 覆盖率的定义

`visible_viewpoints(scene)` 先判每个视点"目标是否被货架挡住"。仓储场景的三个视点里，
`behind-rack` 永远被挡（这正是它的用途：证明遮挡是真实存在的），所以覆盖率的分母是
可行视点数，不是 3。

M2 实测：8 集、每集 109–129 帧、可行视点 2/2 覆盖 100%、`behind-rack` 每集都被判遮挡、
单集墙钟 1.9–3.1 s。

## 两个静默坑

**坑一：量纲**。`wm/dataset.py` 里 `red_fraction` 的阈值最初写成 `0.6 * 255`，
而 `load_episodes` 读进来时已经把图像 `/255`。结果是所有帧都被判"看不见目标"，
可见性标签全 0，可见性 AUC 恒等于 0.500。整个过程不报错，loss 照常下降，
只有对着"基线也是 0.500"这条才发现。修法是把阈值写回 `[0,1]` 尺度，
并在打印里带上"正例占比"（修好后 train 3.4%、val 5.8%）。

**坑二：同 seed 抽到同一个槽**。目标位置最初用 `rng.integers(0, 4)` 选货架槽位，
于是 seed 0/2/3 抽到同一个槽，四集里三集是同一份数据。改成 `slot = seed % len(RACK_X)`
之后连续 seed 才真的覆盖不同格口。这类 bug 不会让任何指标变差，只会让"数据多样性"
这句话变成空话。

两个坑的共同点：**静默失效比报错危险**。所以 M2 的契约测试里有一条是"两集覆盖率都是 1.0
且 route_time > 0"，M3 的判定里有一条是"可见性 AUC 必须高于 persistence 基线"。
只比自己上一轮的数字，这两个 bug 都能活下来。
