# 06 安全层：独立的一票否决

## 三条结构约束

`uavinspect/safety/guard.py` 的设计来自一条教训：安全逻辑写在策略里等于没有安全逻辑。
所以它有三条硬约束：

1. **独立对象**。`SafetyGuard` 不 import 任何策略模块，只吃 `Command` 和状态。
2. **只看最终指令**。策略、遥控、脚本专家给出的指令都先变成 `Command(thrust, torque, stamp, priority)`，
   由 `filter()` 统一裁决。它不关心指令是谁发的。
3. **单方面否决**。输出永远是"执行/改写/拒绝"，没有"协商"。多路指令同周期冲突时
   按 `(priority, stamp)` 取最小的一条，落败方不排队、不延迟执行。

## 模式阶梯

```
NORMAL → HOLD → HOVER → RTL → LAND
```

进入与退出都带迟滞：进入要连续 3 个周期（约 62 ms），退出要连续 30 个周期（约 625 ms）。
只有进入阈值、没有退出阈值时，一次抖动就会让模式在两级之间来回跳，日志看起来像"随机降级"。

升档条件用"在该态待了多久"而不是"离故障多久"：HOLD 0.6 s 后还不能恢复就转 HOVER，
HOVER 3 s 后还没恢复就转 RTL，RTL 12 s 后还没回到 home 就 LAND。

## 物理可信度

只做限幅是不够的。一条 0.5 倍悬停推力的指令完全在硬件量程内，却会让机体直接掉下去。
所以 `_plausible()` 先检查：

- 推力落在悬停推力的 `0.65–1.35` 倍；
- `|torque|` 各轴 ≤ `0.15 N·m`。

不合理就按故障处理（HOLD），不是老实执行。代价写在 ADR-012：真做大机动时必须显式放宽
这个带宽，否则正常爬升也会被拦。

## 四类故障与结果

`scripts/m5_faults.py` 每类故障跑 12 s 闭环：

| 故障 | 注入方式 | 结果 |
|---|---|---|
| A 断流 | 0.8 s 后不再给指令 | 4.04 s 进 HOLD，6.12 s 回 NORMAL，全程不坠 |
| B 陈旧 | 指令心跳停在 0.2 s 前 | 判定为陈旧，不执行旧指令，HOVER 兜住 |
| C 越界 | 推力 5 倍悬停、力矩 3 N·m | 拒绝并记录，切模式 0 次（`rejected_implausible ≥ 3`） |
| D 冲突 | 两路指令同周期到达 | 按优先级取一路，另一路不排队 |

四类全过，最高挡位 HOVER，回稳后位置误差 ≤ 0.007 m。

`scripts/check_safety.py` 另有七条接口级契约，不依赖世界，秒级跑完：3 周期进入、
30 周期退出、陈旧不执行、不合理拒绝、HOLD→HOVER 阶梯、出围栏 RTL、硬限幅。

## 一个量纲坑

`m5_faults.py` 的 `clipped` 检查最初把推力与 `1.0` 比，而推力是牛顿量纲（悬停约 9.81 N），
于是"是否被裁剪"永远为真。这类错误的特征和 M3 的红色像素阈值一样：**检查本身失效，
但结果看起来"抓到了问题"**。修法是对着 `guard.cfg.thrust_abs_max` 比，而不是对着
一个记忆中的数字比。

## 这个安全层不做什么

- 不做几何避障（那是 M1 的斥力层，两者独立）。
- 不做故障诊断（不知道是电机坏了还是模型疯了，只知道"指令不可信"）。
- 不做权限与审计（真实系统里谁改了 safe 参数要留痕，这里没有）。
