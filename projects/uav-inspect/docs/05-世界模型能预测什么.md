# 05 世界模型：它能预测什么，不能预测什么

## 结构

`wm/model.py` 是一个最小可用的潜空间世界模型，四个部件：

| 部件 | 形状 | 作用 |
|---|---|---|
| `Encoder` | 3×64×64 → 128 | 卷积 3→32→64→96，再接 FC |
| `rnn` | GRUCell(128, 128) | 潜状态随动作递推 |
| `dec` | 128 → 3×64×64 | 三级上采样 8→16→32→64，`tanh` 输出到 [-1,1] |
| `vis` | 128 → 1 | 目标可见性（红色像素占比 > 0.3% 作标签） |

解码器是**残差**的：`dec = dec(z) + base`，`base` 是窗口第一帧。
不加残差时，训练早期模型要"从零画出整帧"，而 persistence 基线（直接复制上一帧）
的误差已经很低，模型永远赢不了。加上残差，模型学的是"相对第一帧怎么变"，
这件事在 10 步尺度上才有意义。

## 为什么时程是 10 步

0.1 s 的帧间隔上，persistence 强得离谱：M3 第一次跑 4 步时，模型 0.163、
persistence 0.162，谁也没赢。把时程放到 10 步（约 1 s），persistence 退化到 0.334，
模型的 0.290 才有区分度。

这条经验可以直接迁移：**任何"预测比基线好"的结论，都要先问基线在多长的时程上还强**。
时程太短时最强的模型是"什么都不做"。

## 三个基线，一个判据

`wm/train.py` 里写死了三个基线，不需要额外脚本：

- `persist_mse`：整窗复制第一帧；
- `mean_mse`：复制训练集均值帧；
- `vis_auc_persist`：用"第一帧有没有目标"当可见性预测。

判定要求三项全真：`roll_mse < persist_mse`、`rec_mse < mean_mse`、
`vis_auc > vis_auc_persist`。少一项就 `passed: false`，不看 loss 曲线。

首轮结果（RTX 4060，20 epoch，35.4 s，2.1 M 参数，train 316 / val 96 窗口）：

| 指标 | 模型 | 基线 |
|---|---|---|
| 单步重建 MSE | 0.449 | mean-frame 1.221 |
| 开环 10 步 MSE | 0.290 | persistence 0.334 |
| 可见性 AUC | 0.894 | persistence 0.678 |

可见性正例只占 3.4%（train），所以 AUC 要连着正例占比一起看，
单看 0.894 会高估难度。

## 它不能做的事

1. **不能当规划器用**。64×64、5 Hz、没有物理约束，模型输出的"未来帧"里机体可以穿墙。
   要拿它做 MPC，得先加动力学一致性约束，那是 M4 之后的事。
2. **不能跨场景**。训练数据全部来自同一个仓储场景（4 个货架槽位、同一套光照），
   换场景后可见性头基本失效。
3. **不能替代真实渲染**。它的用途是"预测下一帧的潜状态"，不是"生成好看的图"。
   论文里的世界模型动辄几十亿参数、几分钟生成一段视频，这里 2.1 M 参数、
   35 秒训完，量级差三四个数量级。

## 怎么在开发机上复跑

```bash
pip install numpy torch
python projects/uav-inspect/scripts/m2_inspect.py --episodes 8 --backend rigid
python projects/uav-inspect/wm/train.py --epochs 20 --device cuda
```

第二条命令会重新生成数据（约 20 s，确定性），再训练。产物：
`runs/m3_wm/metrics.json`（含三个基线、`passed`）与 `ckpt.pt`（不进 git）。
判定不通过时先看 `vis_pos_rate`：如果它接近 0，是数据或标签的问题，不是模型的问题。
