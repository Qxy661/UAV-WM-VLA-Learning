# 双具身：同一套 harness 跑多旋翼与机械臂

E11 要证明的不是"我们也会做机械臂"，而是一句更窄的话：**这个仓库的评测与接口不是为多旋翼定制的。**
如果换个具身就得重写评测、重定义指标，那前面的"抽象"就是假抽象。

## 怎么做的

不引第二个仿真器、不引第二个物理引擎。机械臂这一侧只写运动学（`uavinspect/embodiments/arm.py`）：

- 三段连杆，基座偏航 + 两个俯仰关节，`fk(q)` 解析给出末端位置；
- `ik()` 阻尼最小二乘反解，失败就返回最后一步，由调用方按误差判；
- 「动作」定义成关节速度指令 `joint_vel_to_target(q, target)`，30 Hz 一阶积分；
- 状态对象只暴露 `pos`——和无人机 `State.pos` 同名同义。

评测侧一行没改：`scripts/e11_report.py` 用的是和无人机同一套判定（到点容差、步数预算、成功/失败），
指标也是同一组（成功率、到点误差中位与 p90、用时分位）。

## 结果（3 自由度，4 个目标 × 5 个随机初值）

| 指标 | 值 |
|---|---|
| episode | 20 |
| 成功率（5 cm 容差） | 0.800 |
| 到点误差中位 | 0.10 cm |
| 到点误差 p90 | 6.18 cm |
| 用时 p50 | 3.65 s（步数预算 5 s） |

四个失败是**同一个目标** `(0.15, 0.30, 0.20)` 的 4 次试验：全部停在 `q = [1.11, 1.60, -2.00]`，
第二关节顶到 +1.6 rad 的上限——是关节限位，不是 IK 不收敛。换个基座偏航角，或者把这个目标
往外挪 5 cm 就能到。这说明失败可归因、可修，而不是"有时不work"。

## 两边到底共享了什么

| 层 | 多旋翼 | 机械臂 | 是否同一份代码 |
|---|---|---|---|
| 状态 | `State.pos/vel/rot` | `ArmState.pos` | 字段名对齐，类型不同 |
| 动作 | 推力 + 力矩（4 维） | 关节速度（3 维） | 不同，这是具身差异的本体 |
| 策略接口 | `Agent(obs) -> action` | 同 | 同一签名 |
| 评测判定 | 到点容差 + 步数预算 | 同 | 同一函数 |
| 指标 | 成功率 / 误差 / 分位 | 同 | 同一套 |

真正随具身变的只有动作空间和状态里"多出来什么"（无人机有姿态四元数与角速度，机械臂有关节角）。
其余都能复用——这就是抽象该有的形状。

## 不能证明什么

- 不证明操作能力。没有接触、没有抓取、没有关节力矩与重力补偿；这一层的"到点"和真机抓取是两件事。
- 不证明收敛时间可比。机械臂是一阶伺服，无人机是二阶动力学，两个 `seconds` 不可横比，只能各自和预算比。
- 不证明这套抽象能扩到腿足或移动底盘。它们的状态维度与接触模型都不一样，需要另一次验证。

## 复现

```
py -3.9 projects/uav-inspect/scripts/e11_report.py
```

写入 `runs/e11_report/metrics.json`。换目标只需改 `GOALS`，`reachable()` 会先挡掉够不着的点。
