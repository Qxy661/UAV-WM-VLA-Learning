# 工程栈：12 个子系统

这个文件管的是「让仓库像一个真的机器人系统」这件事，不是论文实验清单。每个子系统只有一条规矩：**验收必须是一句能当场判对错的话**，写不出这句话的条目不进这个表。

现有两个项目（`uav-inspect`、`vla-transfer`）已经覆盖了仿真、控制、安全、数据录制、评测、世界模型、π0.5 适配。缺的是把它们连成一条**能从传感器走到部署、且任何一环坏了都能被指出来**的链子。E1–E12 就是补这条链。

## 总图

```
          ┌──────────── E1 仿真基础设施 ────────────┐
          │ 场景库 / 传感器噪声 / 域随机化 / 回放    │
          └───────────────┬──────────────────────────┘
                          ↓ 图像 + IMU + 真值
   E2 感知栈 ──→ E3 状态估计与地图 ──→ E4 规划栈 ──→ E5 控制 ──→ E12 安全(已有)
                          ↓                                  ↓
                    E6 数据平台 ──→ E7 训练基础设施 ──→ E9 模型运维
                          ↓                                  ↓
                    E8 推理服务 ←──────────── 策略/世界模型 ─┘
                          ↓
                  E10 集群协同 / E11 双具身 / E12 可解释回放
```

数据流上的每个箭头都是一次「接口约定」，接口坏了要能被单测抓住，而不是等到闭环失败。

## 各子系统

### E1 仿真基础设施

- **目的**：让仿真可复现、可加噪、可换场景，且承认自己哪里不真实。
- **现状**：刚体 + 解析相机 + 一个仓储场景；无噪声模型、无域随机化、无场景库。
- **交付**：`uavinspect/sim/sensors.py`（IMU 偏置/噪声/量化、相机噪声与运动模糊、深度量化）、`uavinspect/sim/scenarios.py`（参数化场景族：货架数/通道宽/光照/纹理）、`scripts/e1_report.py`（同一 seed 两次逐位一致；不同 seed 的场景差异统计）。
- **接口**：`SensorSuite(cfg, seed).observe(state) -> {"image", "imu", "depth", "t"}`；`Scenario.sample(seed) -> Scene`。
- **验收**：`python scripts/e1_report.py --seeds 8` 输出「同 seed 图像逐位相同=True；IMU 噪声 std 与配置偏差 <5%；场景族覆盖货架数 3–6、通道宽 0.8–1.6 m」。
- **成本**：2–3 天，纯 CPU。
- **文档映射**：`docs/02-世界模型专题/07-关键数据集与基准.md`（数据从哪来）。

### E2 感知栈

- **目的**：不再假设「有真值位姿」，从图像里把目标与障碍找出来。
- **现状**：解析式射线投射，直接知道目标在哪。
- **交付**：`perception/detector.py`（0.5M 参数小检测器，检测红色目标与货架边缘）、`perception/calib.py`（内参/外参标定与重投影误差）、`scripts/e2_train_det.py`、`scripts/e2_report.py`（mAP、单帧延迟、遮挡分档）。
- **验收**：`python scripts/e2_report.py` 输出 `mAP@0.5 ≥ 0.85`、`CPU 单帧 P99 ≤ 15 ms`、并按遮挡比例 0/25/50/75% 四档分别给召回。
- **成本**：3–4 天（训练 20 分钟）。
- **文档映射**：`docs/04-VLM专题/01-遥感VLM.md`、`docs/10-横切判据/02-算力与延迟预算.md`。

### E3 状态估计与地图

- **目的**：把「真值位姿」换成估出来的位姿，并给出可查询的占据地图。
- **现状**：直接用 `State`，没有估计环节。
- **交付**：`estimation/vio.py`（IMU 预积分 + 视觉相对位姿的 EKF-lite）、`mapping/occupancy.py`（2D 占据栅格 + 由栅格算 ESDF）、`scripts/e3_report.py`（ATE、RPE、地图 IoU）。
- **接口**：`Vio.step(imu, image, dt) -> PoseEstimate`；`Occupancy.update(depth, pose)`；`Esdf.query(points) -> dist, grad`。
- **验收**：`python scripts/e3_report.py --seeds 5` 输出 `ATE ≤ 0.15 m`、`RPE(1 s) ≤ 0.05 m`、`地图 IoU ≥ 0.7`；**估计器不得读真值**（单测里把真值字段置 None 仍能跑）。
- **成本**：4–5 天。
- **文档映射**：`docs/02-世界模型专题/08-联合嵌入预测与潜空间世界模型.md`（表示的用途）。

### E4 规划栈

- **目的**：从「反应式斥力」升级到「全局 + 局部」两层，并给出可比的规划指标。
- **现状**：`planning/avoidance.py` 只有斥力。
- **交付**：`planning/global_astar.py`（ESDF 上的 A*，含膨胀与路径平滑）、`planning/local_mpc.py`（10 步、QP 或投影梯度，含动力学约束）、`scripts/e4_compare.py`（三种规划器 × 20 场景）。
- **验收**：同一批 20 个场景，输出成功率 / 路径长度 / 最小间距三项；`A*+MPC` 成功率 ≥ 反应式 +10 个百分点，且最小间距 ≥ 0.6 m；**不允许只报成功率**。
- **成本**：4 天。
- **文档映射**：`docs/03-VLA专题/04-基础模型辅助规划.md`。
- **状态（2026-10-28）**：🟡 全局层已落地（`planning/global_astar.py` + `scripts/e4_compare.py`，局部 MPC 未做）。20 场景 × 45 s：反应式 **0/20**（全部超时悬停在缝口，离货架 0.58–0.62 m，未撞）；A* **20/20**，航程 2.18 m，最小间隙 0.41 m；A*+斥力 与 A* 逐位相同（间隙 0.406→0.411 m）→ **差别在全局规划，不在局部安全距离**。三条验收线里「成功率 +10 点」达成（0→100），「最小间距 ≥0.6 m」未达标（0.41 m，来自栅格膨胀 0.30 m），如实记着。讲解见 `docs/10-规划器对照.md`。

### E5 控制进阶

- **目的**：给控制器一个「模型预测」的对照，量化级联 PD 的代价。
- **现状**：Lee 型几何控制 + 一阶电机滞后。
- **交付**：`control/mpc_control.py`（线性化 MPC，QP 求解）、`control/disturbance.py`（扰动观测器）、`scripts/e5_compare.py`（阶跃/风扰/载荷变化三类工况）。
- **验收**：风扰 3 m/s 下位置 RMSE 比 PD 低 ≥ 30%；计算耗时 P99 ≤ 2 ms（48 Hz 留 20% 余量）。
- **成本**：3–4 天。
- **文档映射**：`docs/01-基础概念/05-无人机vs地面机器人.md`。

### E6 数据平台

- **目的**：数据坏了要在入库时被拒绝，而不是训练完才发现。
- **现状**：`obs.npz + meta.json + manifest.json`，有划分但无校验门。
- **交付**：`data/registry.py`（数据集版本、内容哈希、字段 schema）、`data/validate.py`（十二条硬规则）、`scripts/e6_validate.py`（`--strict` 时非零退出）、`scripts/e6_stats.py`（分布报表）。
- **校验规则（每条都要能失败）**：帧数与时间戳数一致；时间严格单调；图像 shape/dtype 固定；动作在 [-1,1]；四元数模长 ∈ [0.99,1.01]；state 无 NaN；episode 内无重复帧；划分按 episode 且无交叉；测试场景 seed 未出现在训练集；指令模板与划分一致；manifest 与磁盘一致；覆盖率字段存在。
- **验收**：`python scripts/e6_validate.py --root /root/work/data/uav96 --strict` 在干净数据上退出码 0；故意注入三条坏数据（少一帧、时间回退、动作越界）后退出码非 0 且逐条指出。
- **成本**：2–3 天。
- **文档映射**：`docs/10-横切判据/06-数据泄漏与划分.md`。

### E7 训练基础设施

- **目的**：任何一次训练都能复现、能续、能被查。
- **现状**：两个训练脚本，超参走 argparse，无配置快照、无断点续训一致性检查。
- **交付**：`trainlab/config.py`（YAML + 覆盖 + 落盘快照）、`trainlab/runner.py`（种子、AMP、断点、日志 JSONL、异常自动存现场）、`trainlab/consistency.py`（离线误差 vs 闭环成功率的联合检查）、`scripts/e7_sweep.py`（8 组并行）。
- **验收**：① 同一 config 两次训练 500 步 loss 逐位差 < 1e-7；② 中断后从 ckpt 续训，loss 曲线与连续训练偏差 < 1e-6；③ `consistency` 在同一批数据上同时报离线 RMSE 与闭环成功率，两者序不一致时给出警告（当前 BC 就是这种情况：离线 0.027 N、闭环 0/20）。
- **状态（2026-10-25）**：🟡 部分落地。scripts/e7_consistency.py 已能用；在 BC（扰动数据）上跑出：推力 nRMSE 0.05、tau_x 0.10、tau_y 0.23、**tau_z 0.77**，闭环 0/20 → 判定 oth_bad，瓶颈在偏航力矩通道，不是「纯协变量漂移」。这条结论推翻了早前只报 0.027 N 推力误差的说法（那是悬停段常数动作撑出来的）。随后做了 omega 动作空间对照（1200 集、val_mse 0.0947、闭环 0/20），说明换表示不解决问题：瓶颈在数据规模与闭环偏差。
- **成本**：3 天。
- **文档映射**：`docs/10-横切判据/09-训练工程最小集.md`。

### E8 推理服务

- **目的**：服务端要能说清「一次推理多久、批量多大、超时怎么办」。
- **现状**：`serve_uav.py` 单请求、无批处理、无超时策略。
- **交付**：`serving/server.py`（请求队列 + 动态批处理 + 每请求 deadline）、`serving/onnx_path.py`（导出 ONNX 并用 onnxruntime 跑同一批输入对数值）、`scripts/e8_bench.py`（QPS、P50/P99、批大小曲线）。
- **验收**：batch=1 与 batch=8 的 P99 都报；ONNX 与 PyTorch 输出最大绝对差 < 1e-3；超时请求返回「沿用上一块」而不是阻塞。
- **成本**：3 天。
- **文档映射**：`docs/10-横切判据/10-导出与尾部延迟.md`。

### E9 模型运维

- **目的**：模型、数据、指标三者绑定，可追溯、可回滚。
- **现状**：指标散在 `runs/*/metrics.json`。
- **交付**：`mlops/registry.py`（注册表：run_id、git sha、数据哈希、配置、指标、ckpt 路径）、`mlops/drift.py`（输入分布 PSI/KL 报警）、`scripts/e9_report.py`（列出所有 run 与最优）。
- **验收**：`python scripts/e9_report.py --best success_rate` 给出 run 表；人为把测试集亮度整体 +20% 后 drift 报警触发；注册表里任意 run 能按 run_id 还原配置与数据哈希。
- **成本**：2–3 天。
- **文档映射**：`docs/10-横切判据/01-口径不可横比.md`。

### E10 集群协同

- **目的**：多机不只是避让，还要分工与容错。
- **现状**：四机避让（最小间距 1.165 m）。
- **交付**：`fleet/allocation.py`（拍卖式任务分配 + 重分配）、`fleet/comm.py`（丢包/延迟/带宽限制的通信仿真）、`scripts/e10_report.py`（4 机 6 点，丢包 0/15/30%）。
- **验收**：丢包 30% 时分配仍收敛（≤ 5 s）；任务完成时间与集中式最优差距 ≤ 15%；单机失效后剩余任务在 3 s 内被重新分配。
- **状态（2026-10-28）**：✅ 分配与通信两层已落地，报告可跑。20 个随机问题、4 机 6 点、最优值用子集 DP（并以 4^6 穷举交叉验证）：无丢包时顺序拍卖 gap 1.097、全局贪心 1.084；30% 丢包时拍卖 1.179、贪心 1.123。重分配通信 84–93 ms（20 ms 单向延迟，约 4–5 个往返）。三条验收线里「差距 ≤ 15%」在 30% 丢包下为 1.179，**未达标**，如实记着；「3 秒内重分配」远超要求（百毫秒级）。
- **为什么 gap 停在 10% 量级**：顺序拍卖逐任务决策，某个点把一台机器排满后，后续点只能退而求其次；全局贪心每步重算全部 (机器, 点) 对，所以略好且更抗丢包。要压到 15% 以内需要「重估 + 局部交换」这一步，还没做。
- **成本**：4 天。
- **文档映射**：`projects/uav-inspect/docs/09-多机分配与通信.md`。

### E11 双具身

- **目的**：证明「具身抽象」不是为无人机定制的一次性接口。
- **现状**：`Embodiment` 只有无人机实现。
- **交付**：`embodiments/arm.py`（6 自由度机械臂 + 抓取任务，复用同一 rigid 后端）、`scripts/e11_report.py`（同一 harness 跑两种具身）。
- **验收**：评测 harness 代码零改动即可跑机械臂；两种具身共用 `TaskSpec/run_episode/evaluate/compare`；成功率各自有 bootstrap 区间。
- **成本**：4–5 天。
- **文档映射**：`docs/03-VLA专题/07-数据、预训练与跨具身.md`。

### E12 可解释与回放

- **目的**：失败能被看见，而不是只看一个 0/20。
- **现状**：轨迹图 + metrics.json。
- **交付**：`tools/replay.py`（单文件 HTML：逐帧画面 + 到目标距离 / 推力 / 画面红像素占比三条曲线）、`tools/saliency.py`（单点遮挡敏感度：把图切成 N×N 块逐块涂掉，看 3 维子目标预测位移多少米，并统计每块红色像素占比与两者的相关系数）。
- **验收**：`python tools/replay.py --episode <dir> --out runs/replay/x.html` 产出可离线打开的单文件 HTML；saliency 图能指出「遮住货架区域时动作变化最大」。
- **状态（2026-10-28）**：✅ 两个工具已落地并在小数据上跑通。replay：71 帧 / 900 控制步的一集渲成 114 KB 单文件 HTML，`red_max_pct` 2.91%、`dist_min` 1.43 m 打到 stdout 供回归比对。saliency：3 集 × 3 帧、4×4 网格，`sensitivity_max_cm` 3.13、`sensitivity_p90_cm` 2.54、`corr_heat_red` −0.016（该模型几乎不看红点，与「盲训练不掉分」一致；正式数字等 `runs/sg_rel2/ckpt.pt` 重跑）。
- **为什么值得有**：盲消融回答「不看图能不能做」，遮挡敏感度回答「它在看哪里」。只有前者时，一次打平的盲消融既可能意味着视觉冗余，也可能意味着训练没学到；后者能把这两种解释分开。
- **成本**：2–3 天。
- **文档映射**：`projects/uav-inspect/docs/07-评测口径.md`。

## 砍掉什么

- 真机与硬件在环：没有设备，也不做假承诺。
- ROS2 / PX4 集成：环境成本高于收益，接口留了 `Agent(obs)->action`。
- Jetson 上跑 TensorRT 引擎：只做 ONNX 图与延迟模型，写明「不是端侧实测」。
- 完整 SLAM 后端（回环、全局优化）：E3 只做 VIO-lite + 占据栅格，够支撑规划即可。
- C++ 推理：Python 侧把接口与预算写清楚就够。
