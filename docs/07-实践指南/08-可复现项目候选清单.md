# 可复现项目候选清单

> 预计阅读：15 分钟 | 前置知识：了解无人机基础、Python环境配置
>
> 本文档收录与无人机+VLA/VLM/世界模型方向贴合的、可单机复现的开源项目。
> 每个项目标注了难度、硬件需求、预计耗时和与无人机方向的贴合度。
> 供后续选择实际复现时参考。

---

## 选择标准

| 维度 | 说明 |
|------|------|
| **方向贴合** | 必须与无人机/UAV + VLA/VLM/世界模型直接相关 |
| **可复现性** | 有完整代码、文档、数据集，社区活跃 |
| **硬件门槛** | 单 GPU（RTX 4060/4070 级别）或纯 CPU 可跑 |
| **学习价值** | 能帮助理解核心概念，不只是跑通 demo |
| **耗时合理** | 1-7 天可完成，不是需要数周训练的大项目 |

## A 类：直接无人机项目（强烈推荐）

### A1. gym-pybullet-drones — 无人机 RL 控制仿真

| 项目 | 信息 |
|------|------|
| **GitHub** | [utiasDSL/gym-pybullet-drones](https://github.com/utiasDSL/gym-pybullet-drones) |
| **Stars** | ~2,000 |
| **硬件需求** | 纯 CPU 即可（PyBullet 物理引擎） |
| **难度** | ★★☆☆☆ 入门级 |
| **预计耗时** | 1-2 天 |
| **贴合度** | ★★★★★ 无人机控制核心 |

**项目简介**：基于 PyBullet 的四旋翼 Gymnasium 仿真环境，支持单机/多机 RL 训练。提供 PID 控制示例和 PPO 训练脚本，可对接 Betaflight/Crazyflie 固件做 SITL 测试。

**为什么推荐**：
门槛最低的一个：纯 CPU、代码量小，而且它是 C1 的起点——在同一个环境上接 DreamerV3 就是 C1，换个策略头就变成 VLA 控制器的试验场。

**复现内容**：
1. 运行 PID 悬停 demo
2. 用 PPO 训练悬停策略
3. 可选：多机编队、加入视觉观测

### A2. safe-control-gym — 安全约束无人机控制

| 项目 | 信息 |
|------|------|
| **GitHub** | [utiasDSL/safe-control-gym](https://github.com/utiasDSL/safe-control-gym) |
| **Stars** | ~879 |
| **硬件需求** | 纯 CPU（测试环境为 i7 无 GPU） |
| **难度** | ★★★☆☆ 中级 |
| **预计耗时** | 2-3 天 |
| **贴合度** | ★★★★★ 安全飞行核心 |

**项目简介**：PyBullet 四旋翼环境 + CasADi 符号动力学，内置 PID/LQR/iLQR/MPC/SAC/PPO 等多种控制器和安全滤波器（MPSC、CBF）。

**为什么推荐**：
这批项目里唯一能把 PID、LQR、MPC、SAC/PPO 和安全滤波器（MPSC、CBF）放进同一个环境对比的。想动手验证[研究空白与机会](../08-研究前沿与开放问题/02-研究空白与机会.md) 2.3 节「在动作输出端接 CBF」那个想法，这里是现成的试验台。

**复现内容**：
1. 对比 PID vs LQR vs MPC 控制效果
2. 训练 SAC/PPO 策略
3. 加入安全约束（CBF）观察效果差异

1. 配置 LLM API，运行自然语言悬停/导航 demo
2. 修改 prompt 模板，观察行为变化

## 思考题

1. **查表找矛盾**："快速体验路线"标称是"1 周，纯 CPU/轻量 GPU"。把它列的 7 天项目逐个对照上面的硬件汇总表 —— 这条路线真能在一张 8 GB 卡上走完吗？哪一天会卡住？

2. **路线设计**：两条路线（快速体验 1 周 / 深度学习 2-3 周）是按什么划分的？为什么 A3 UAV-Flow 被放在第 2 周而不是第 1 周？

3. **读表方法**：硬件汇总表里用的是"✅推理 / ✅LoRA / ✅微调 / ✅全量"这种动词，而不是简单的"能跑/不能跑"。为什么要做这个区分？选项目时它帮你避免了什么误判？

4. **标准反思**：选择标准里有一条"1-7 天可完成，不是需要数周训练的大项目"。这条标准排除了哪一类项目？它对"学习"来说是合理的，但可能付出什么代价？

5. **缺口判断**：C 类（世界模型方向）只有两个项目，且整体标注为"可选"。对照 A 类和 D 类的规模，这个数量差说明了什么？如果你想补一个 C 类项目，你会从什么方向找？

<details><summary>参考答案</summary>

1. **走不完，会卡在第 6 天。** 路线里第 6 天是 D3 Falcon，而硬件汇总表把它标成 8 GB ❌、16 GB 才 ✅推理 —— 也就是说它需要 16 GB 卡。其余六天都对得上：A1、A5 和 B5 Flightmare 在 CPU 列就是 ✅，B2 YOLO-OBB 在 8 GB 已经是 ✅训练，A4 GeoChat 和 D1 RemoteCLIP 在 8 GB 是 ✅推理。所以这条路线实际是"1 周 + 一张 16 GB 卡"。

2. 划分标准是**硬件门槛**：快速体验路线标称纯 CPU/轻量 GPU，深度学习路线要求 GPU 16 GB+。A3 UAV-Flow 放第 2 周有两个原因 —— 一是硬件，表里它在 8 GB 只能推理、24 GB 才能微调；二是认知顺序，它对应第 2 周"理解 VLA 端到端控制"这个目标，需要先有前面 VLM/VLA 的概念铺垫。

3. 因为这个领域"能跑起来"和"能改得动"是两种完全不同的门槛。同一张 8 GB 卡，A3 只能做推理，A4 只能推理，而在 16 GB 上 A4 已经能跑 LoRA。如果表里只写"能跑"，很容易带着"我 8 GB 也能复现 GeoChat 微调"的预期开工，然后卡在 OOM 上。**写清动词，等于提前告诉你这张卡允许你做到哪一步**，也顺带说明升一档卡能解锁什么。

4. 排除的是**需要从头训练大模型**的项目 —— 数周训练、多卡、大数据集那一类。对学习阶段合理：目标是理解机制而不是刷指标，短周期才能快速建立"改一个东西 → 看到结果变化"的反馈闭环。代价是容易停在"跑通"：只做推理和微调，对训练动态（数据规模怎么影响收敛、loss 长什么样、失败模式有哪些）的体感不足，而这恰恰是研究里最难、也最需要经验的部分。

5. 说明**世界模型方向的可复现性明显更差** —— A 类有 7 个、D 类有 5 个，C 类只有 2 个。原因不难推：训练一个世界模型本身就要大规模数据、算力和长时间，与上面"1-7 天可完成"的选择标准天然冲突，所以只能标"可选"。要补 C 类，应该往**门槛被削平过的**方向找：已经放出了预训练权重、或本来就设计成小规模可训的项目（比如基于现成仿真器做小规模世界模型实验），而不是那些复现一次要几百 GPU 小时的论文。
