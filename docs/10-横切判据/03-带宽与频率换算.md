# 视觉带宽到动作频率的换算

> **定位**：把"感知多快、动作多快"之间的落差写成一条可算的链路，并导出 chunk 长度的下限
> **本篇 KP**：KP-X03
> **读完后应能**：①列出从曝光到执行器的五段延迟 ②算出策略频率与内环频率的比值，得到 chunk 长度下限 ③解释为什么 50 Hz 直连 VLA 不成立
> **判据**：给定相机帧率、推理延迟与内环频率，能算出 chunk 长度下限并说明低于它会发生什么
> 预计阅读：12 分钟 | 前置知识：KP-X02

---

## 五段延迟

一条动作从"看到"到"动起来"要过五段：

| 段 | 典型量级 | 决定因素 |
|---|---|---|
| 曝光与读出 | 5–33 ms | 帧率与快门方式 |
| 预处理与传输 | 2–10 ms | 缩放、色彩空间、共享内存 |
| 前向推理 | 20–300 ms | KP-X02 的预算 |
| 后处理与仲裁 | 1–5 ms | 限幅、安全层、队列 |
| 执行器响应 | 10–50 ms | 电机时间常数、控制周期 |

加起来 40 ms 到 400 ms，跨一个数量级。第三条是主项，且随模型规模线性增长。

## 比值决定 chunk

设内环频率 f_c（控制律的执行频率，例如 250 Hz），策略频率 f_p（每次前向后能给出新动作的频率）。一次前向给出的动作必须覆盖到下一次前向完成之前：

```
chunk 长度 N ≥ ceil(f_c / f_p)
```

若 f_c = 250 Hz、f_p = 5 Hz，则 N ≥ 50。也就是说单次推理必须给出 50 个控制周期的动作序列，否则中间有空洞。

反过来看"VLA 直连 50 Hz"这件事：50 Hz 意味着 20 ms 内完成从曝光到执行的全链路。而一个 0.3B 的多模态模型在机载板上的前向就要 150 ms 量级。差 7 倍以上。所以"VLA 直接输出 50 Hz 控制量"在算力上不成立，能成立的只有两种形态：

1. 策略低频输出动作块，控制器高频跟踪（chunk + 插值）；
2. 策略只输出设定点或代价权重，底层用 MPC／几何控制补频率。

`code/p_chunk_horizon.py` 扫了提交长度：chunk 太短时闭环跟不住（每个周期都在等新动作），太长时前段过期（执行的是几帧之前的计划），中间存在一个最优区间。这个 demo 的结论不是"越长越好"，而是"存在与延迟匹配的长度"。

## 带宽的另一头

视觉输入本身也有带宽：224×224×3 的 uint8 每帧 150 KB，30 Hz 三路就是 13 MB/s，走 USB 或网络都要占信道。压分辨率看起来免费，代价体现在 `code/w_token_budget.py`：把视觉 token 压下去，先崩的是定位而不是描述。原因是定位依赖高分辨率空间细节，语义描述依赖低分辨率全局结构。所以降带宽要按任务分配，不能一刀切。

## 算例

园区巡检，三路 224²、5 Hz 策略、250 Hz 内环、单次推理 120 ms：

- f_p = 1 / 0.12 ≈ 8.3 Hz（忽略其他段）
- N ≥ ceil(250 / 8.3) = 31
- 若把模型换成 3 倍大的，推理 360 ms，f_p ≈ 2.8 Hz，N ≥ 90

N 从 31 涨到 90，意味着动作头要预测 0.36 秒之后的轨迹，误差预算也随之放大。这就是"模型变大"的隐性代价：不只是慢，是要求动作头看得更远。

## 判据表

| 检查项 | 通过条件 | 不通过时 |
|---|---|---|
| 五段延迟 | 每段有量级估计，不合并成"总延迟" | 至少给出推理段与其余段的比值 |
| 频率比 | f_c 与 f_p 都写明 | 只写"实时"时按不可判定处理 |
| chunk 下限 | N ≥ ceil(f_c / f_p)，且有余量 | 余量 < 1.5 倍时标注风险 |
| 插值方式 | 写明线性／样条／零阶保持 | 不写默认零阶保持，会有台阶 |
| 过期处理 | 有超时丢弃规则 | 缺规则则队列会积压并漂移 |

## 边界

这条换算假设延迟稳定。实际延迟有长尾，P99 常是 P50 的 2–4 倍，用均值算出的 N 在长尾时会不够。工程上的补法不是加大 N，而是让控制桥在断流时切到定高／悬停（见 KP-X08），把"来不及"变成"降级"。
