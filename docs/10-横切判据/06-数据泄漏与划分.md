# 数据泄漏与划分纪律

> **定位**：列出航拍与飞行数据里最常见的四条泄漏路径，并给出可执行的划分规则
> **本篇 KP**：KP-X06
> **读完后应能**：①在一份数据集描述里找出同场景帧、同轨迹、预处理拟合三条泄漏 ②按场景或轨迹做分组划分 ③判断一次"提升"是不是泄漏带来的
> **判据**：给一份数据集描述与划分方式，能指出至少两条泄漏路径，并写出修改后的划分
> 预计阅读：12 分钟 | 前置知识：训练／验证／测试集的基本用法

## 泄漏为什么在航拍数据上更重

图像分类的泄漏通常是重复样本。飞行数据不一样：同一段飞行里相邻帧只差 33 ms，画面几乎相同；同一栋楼会被不同架次、不同角度拍到；同一条航线的场景分布高度集中。

于是"随机划分帧"几乎等于把测试集复制进了训练集。模型学到的是纹理记忆，报出的指标是记忆准确率。

## 四条路径

| 路径 | 表现 | 检查方法 | 修法 |
|---|---|---|---|
| 同场景帧 | 相邻帧跨训练与测试 | 看文件名或时间戳是否连续 | 按场景分组划分（group split） |
| 同轨迹 | 同一架次的前后段被分到两边 | 按 episode／架次 ID 分组 | 整段轨迹进同一侧 |
| 预处理拟合 | 归一化均值方差、词表、聚类中心在全量数据上算 | 查统计量在哪一步计算 | 统计量只用训练集拟合，再作用到验证／测试 |
| 测试集调参 | 用测试集选超参或早停 | 查实验记录里选择依据的来源 | 划验证集，测试集只在最后动一次 |

第四条最容易被自己骗：早停看着是"防止过拟合"，但如果早停依据测试集损失，测试集就参与了训练决策。

## 本库的两个具体例子

`code/a_worldmodel_rssm.py` 早先用训练那批轨迹同时算评估误差，属于第二条。现已改成 192 条训练 / 64 条评估：损失曲线真实，但它证明的是拟合能力，不是泛化；泛化看那 64 条上的数字。

`code/e_gsc_safety.py` 早先四组对照共用同一条随机数流（只种一次种子），而且每一轮都重铺出生点。于是"只改一个变量"这个前提不成立：组间的差异里混了出生点分布的差异。现已改成同一场景的 GSC 开/关两组传同一个 `seed`，两组飞同一批起点。这类混淆比泄漏更隐蔽——泄漏让结果虚高，混淆连结论的方向都可能反过来。

## 划分粒度怎么选

| 任务 | 该按什么分组 | 理由 |
|---|---|---|
| 单场景重建 | 按轨迹 | 同轨迹内视角高度相关 |
| 跨场景泛化 | 按场景（建筑／街区） | 这才是"没见过的地方" |
| 跨城市／跨季节 | 按城市／按月份 | 光照与地物分布整体变化 |
| 时序预测 | 按时间切分，不随机 | 随机切会把未来信息带进过去 |
| 语言条件任务 | 按指令模板分组 | 同模板的不同说法是近重复 |

粒度越粗，报出的数越低，结论越可信。反过来，如果换粗粒度后指标几乎不掉，第一反应应该是"指标没测到泛化"，而不是"模型很强"。

## 判据表

| 检查项 | 通过条件 | 不通过时 |
|---|---|---|
| 分组键 | 写明按什么分组（场景／轨迹／时间） | 写"随机划分"即视为存在泄漏风险 |
| 统计量 | 归一化、词表、聚类只拟合训练集 | 全量拟合则重跑 |
| 选择过程 | 超参与早停只看验证集 | 看过测试集则该结果作废 |
| 未见场景 | 单列"未见场景"指标 | 只有混合指标时结论降级 |
| 重复检测 | 做过近重复帧检测（哈希或相似度） | 未做则标注"未检测" |

## 边界

小数据下严格分组会让方差变大，指标看上去不稳。这不是放松划分的理由，而是报置信区间的理由：n 个场景的均值配区间，比一万个帧的均值更诚实。判断标准是独立单元数，不是样本数——一千帧来自十个场景，独立单元是十。
