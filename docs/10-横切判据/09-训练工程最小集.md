# 训练工程最小集

> **定位**：给出"别人能一条命令跑起来"的最小工程集合，以及每个部件缺失时的具体后果
> **本篇 KP**：KP-X09
> **读完后应能**：①列出一训练能被复现所需的七个部件 ②判断一份代码里哪些缺失会导致数字不可信 ③设计断点续训的一致性检查
> **判据**：给一个训练脚本，能指出它离"他人一条命令复现"还差哪几项，并说明每项缺失会让什么数字失效
> 预计阅读：12 分钟 | 前置知识：PyTorch 训练循环

---

## 七个部件

| 部件 | 最小要求 | 缺失后果 |
|---|---|---|
| 配置 | 全部超参进配置文件，代码里不留魔法数 | 改一个数要翻源码，复现靠口头 |
| 环境 | 依赖与版本锁定（requirements 或 lock 文件） | 半年后装不出同样的环境 |
| 种子 | 训练与评估各自种子，可覆盖 | 结果不可重跑，调参变成抽奖 |
| 数据划分 | 划分规则写进代码，不手工切 | 换一次划分结论就变 |
| 检查点 | 保存模型、优化器、步数、随机数状态 | 中断即重来，长训练不可行 |
| 日志 | 结构化指标（标量 + 步数），而非 print | 曲线画不出来，问题定位靠猜 |
| 评估 | 独立的评估入口，用 hold-out | 评估混在训练循环里，容易偷看 |

这七项的排序不是随意的。前两项决定"能不能装上"，中两项决定"结果是不是真的"，后三项决定"能不能改"。

## 三个本库的具体反例

`code/b_lang_cond_policy.py` 用最后一个 minibatch 的训练损失当最终指标。这违反"评估独立"：该值既受批次顺序影响，也完全不知道 hold-out 表现。

`code/a_worldmodel_rssm.py` 的评估段直接复用训练轨迹。这违反"数据划分"：报出的误差是拟合误差。

`code/e_gsc_safety.py` 的四组对照共用一条随机数流，且每轮重铺出生点。这违反"种子"：组间差异里混了采样差异，唯一变量前提不成立。

三个反例的共同点：代码能跑、图能画、结论方向可能还对，但数字不可引用。这就是"玩具代码"与技术债的分界线——不是难不难，是可不可信。

## 检查点与续训一致性

最小实现：

```python
ckpt = {"model": model.state_dict(), "opt": opt.state_dict(),
        "step": step, "seed": seed,
        "rng": {"torch": torch.get_rng_state(), "numpy": np.random.get_state(),
                "python": random.getstate()}}
```

续训一致性检查：从第 500 步存盘，跑到 1000 步记录 loss 序列；再从 500 步重载跑到 1000 步，比较两段 loss 是否逐位相同。差在 1e-7 以内算通过，差在 1e-3 说明有非确定性来源（常见是 DataLoader 的 worker 顺序与 CUDA 非确定算子）。

完全确定性在 GPU 上代价很高，通常不做。可行折中：固定种子 + 记录非确定算子开关 + 报多次运行的均值方差。

## 判据表

| 检查项 | 通过条件 | 不通过时 |
|---|---|---|
| 一条命令 | README 里的命令能从头跑到出图 | 需要手工改路径或补文件则不算 |
| 配置外置 | `grep` 源码找不到手改的超参 | 存在则配置快照不完整 |
| 环境锁定 | 版本号精确到 patch | 只写包名不算 |
| 种子覆盖 | `--seed` 可覆盖且进入日志 | 写死种子时无法做方差实验 |
| 续训一致 | 重载后续 500 步 loss 与原始差 < 1e-7 | 差大则续训不可信 |
| 指标结构化 | 标量带步数，可导出 CSV | 只有 print 则无法比较 |
| 评估独立 | 评估脚本单独存在，不 import 训练循环 | 共用则容易泄漏 |

## 边界

这套最小集服务于"一个人维护、别人能接手"的规模。团队规模上去后还要加：数据版本控制、实验登记、分布式一致性、混合精度数值稳定性检查。但七项缺失时，加再多基础设施也救不回来——因为问题不在工具，在于数字从一开始就没有来源。

判断一个项目是否跨过这条线，最快的办法是问："把你的仓库给我，我多久能复现你论文里那张表？"答案超过半天，就是还没跨过。
