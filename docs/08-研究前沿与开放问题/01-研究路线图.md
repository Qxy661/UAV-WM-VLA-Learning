# 从学习到研究：无人机智能体研究路线图

> 预计阅读：15 分钟 | 前置知识：已完成基础概念学习（Part 1）

---

## 为什么需要这份路线图

学习现有论文是起点，但科研的核心是**发现和解决问题**。本文档帮你从"读懂论文"过渡到"做出贡献"。

```
学习者路径:  读论文 → 理解方法 → 复现实验 → 完成
研究者路径:  读论文 → 批判思考 → 发现问题 → 提出假设 → 设计实验 → 验证 → 贡献
```

---

## 科研流程五步法

### Step 1: 建立领域地图（已完成）

通过本项目的 Part 1-4，你已经建立了：
- VLM、VLA、世界模型的概念框架
- 三大技术族的发展脉络
- 无人机领域的特殊挑战

**检验标准**：能用一张图画出 VLM→VLA→世界模型的关系，并指出无人机与地面机器人的 3 个核心差异。

### Step 2: 深度论文精读

不是泛读，而是对关键论文做**批判性分析**：

| 分析维度 | 要问的问题 |
|----------|-----------|
| **问题定义** | 论文要解决什么问题？这个问题重要吗？ |
| **假设** | 方法建立在哪些假设上？这些假设在无人机场景下成立吗？ |
| **实验设计** | 实验是否充分？消融实验是否完整？ |
| **局限性** | 作者承认了哪些局限？还有哪些没说的？ |
| **可复现性** | 代码是否开源？数据是否公开？结果能否复现？ |
| **与无人机的关联** | 该方法能直接用于无人机吗？需要哪些修改？ |

**具体做法**：
1. 选 3-5 篇核心论文（从 [论文导读合集](../06-论文导读合集/) 中选）
2. 对每篇论文填写上述分析表格
3. 找出论文之间的**共识和分歧**
4. 记录你的**疑问和想法**

### Step 3: 识别研究空白

这是从学习者到研究者的关键转折。研究空白通常出现在：

```
┌─────────────────────────────────────────────────┐
│              研究空白的四种来源                    │
├─────────────────────────────────────────────────┤
│                                                 │
│  1. 方法空白：某类问题还没有好的解法              │
│     例：无人机实时VLA控制的延迟问题               │
│                                                 │
│  2. 场景空白：某方法在A领域成熟但B领域未探索      │
│     例：世界模型在游戏/自动驾驶成熟，无人机少见   │
│                                                 │
│  3. 评估空白：缺乏公平的对比基准                  │
│     例：无人机VLA没有统一的sim-to-real评估协议    │
│                                                 │
│  4. 融合空白：两个独立方向的交叉点                │
│     例：VLM场景理解 + 世界模型预测 → 无人机规划   │
│                                                 │
└─────────────────────────────────────────────────┘
```

**具体做法**：
1. 阅读每篇论文的 "Limitations" 和 "Future Work" 部分
2. 对比多篇论文，找共同提到但未解决的问题
3. 思考"无人机场景下，哪些问题更难？"
4. 参考 [研究空白与机会](02-研究空白与机会.md) 中的分析

### Step 4: 提出研究问题

好的研究问题需要满足 **FINER 标准**：

| 标准 | 含义 | 无人机领域示例 |
|------|------|---------------|
| **F**easible | 可行 | "用单GPU在仿真中训练无人机VLA" ✓ |
| **I**nteresting | 有趣 | "让无人机听懂自然语言指令" ✓ |
| **N**ovel | 新颖 | "用Transformer做无人机目标检测" ✗（太常规） |
| **E**thical | 合规 | "用无人机做人群监控" ✗（伦理敏感） |
| **R**elevant | 相关 | "提升无人机VLA的sim-to-real迁移" ✓ |

**研究问题模板**：
> 在 [场景] 下，如何解决 [问题]，使得 [指标] 提升？

示例：
- "在无人机FPV视角下，如何将世界模型的推理延迟降低到50Hz以下，使得实时避障成为可能？"
- "在缺乏真实飞行数据的情况下，如何利用视频生成世界模型合成训练数据，使得VLA策略的sim-to-real差距缩小30%？"

### Step 5: 设计实验验证

```
研究假设 → 实验设计 → 数据收集 → 模型训练 → 评估对比 → 结论
    ↑                                                    │
    └────────────── 迭代修正 ←──────────────────────────┘
```

**实验设计清单**：
- [ ] 基线选择：至少 2 个有代表性的基线方法
- [ ] 数据集：使用公开基准（如 UAVBench、AeroVerse）或说明自建数据集的必要性
- [ ] 评估指标：选择领域标准指标（成功率、推理延迟、泛化能力等）
- [ ] 消融实验：验证每个组件的贡献
- [ ] 统计显著性：多次运行取均值和标准差

## 推荐的研究切入点

基于当前领域状态，以下方向适合入门研究：

### 方向 A：VLM + 无人机场景理解（入门友好）
- **问题**：通用 VLM 在无人机俯视/斜视视角下表现差
- **方法**：在 GeoChat/UAVBench 上做 fine-tuning，对比通用 vs 领域适配效果
- **工具**：GeoChat 代码 + 无人机数据集
- **预期贡献**：一个轻量化的无人机视角适配方案

### 方向 B：世界模型 + 无人机仿真（中等难度）
- **问题**：无人机仿真器（AirSim/PX4 SITL）与真实环境差距大
- **方法**：用世界模型学习飞行动力学，替代部分物理仿真
- **工具**：gym-pybullet-drones + DreamerV3
- **预期贡献**：一个基于世界模型的无人机仿真增强方案

### 方向 C：VLA + 语言条件飞行控制（前沿方向）
- **问题**：现有 VLA 模型推理延迟高，无法满足无人机 50Hz 控制需求
- **方法**：知识蒸馏/量化，将大 VLA 压缩为轻量模型
- **工具**：OpenVLA/UAV-Flow + TensorRT
- **预期贡献**：一个实时化的无人机 VLA 部署方案

## 思考题

1. **自我诊断**：用"研究能力自评"表给自己打分，你会先补哪一格？对应到五步法，你该从哪一步开始做？

2. **可行性排序**：按 FINER 标准逐个评估方向 A、B、C，哪个最容易做出来？最容易踩的坑是什么？

3. **空白归类**：把方向 A、B、C 分别归到"方法空白 / 场景空白 / 评估空白 / 融合空白"里，并说明依据。

4. **实验设计**：假设你选定方向 C，按 Step 5 的清单列出你的基线与消融，并指出清单没覆盖、你必须自己补的一项。

5. **风险预判**：Step 3 把"缺乏统一的 sim-to-real 评估协议"列为评估空白。这对你选方向意味着什么？

2. 最容易的是 A。它的工具是 GeoChat 代码加无人机数据集，方法是在 GeoChat/UAVBench 上做 fine-tuning，不需要真实无人机和额外算力，是三者里最可行的，问题本身（通用 VLM 在俯视/斜视视角下表现差）也直接相关。最容易踩的坑是 Novel：文档明确说"用 Transformer 做无人机目标检测"这类太常规的不算新颖，所以 A 必须做成视角适配方案，而不只是再跑一次微调。B 需要 gym-pybullet-drones + DreamerV3，属中等难度；C 需要 OpenVLA/UAV-Flow 加 TensorRT，还要满足 50Hz 的硬指标，最重。

3. A 属于场景空白——VLM 在通用和遥感领域已有成熟方案，无人机俯视/斜视视角这个场景还没被充分探索，正对应文档所说的"某方法在 A 领域成熟但 B 领域未探索"。B 落在场景空白与方法空白的交叉：世界模型在游戏、自动驾驶已经成熟、无人机少见，正是文档给场景空白举的原例；而"用世界模型学习飞行动力学、替代部分物理仿真"又是在改造仿真这条技术路线本身。C 属于方法空白，文档给方法空白举的例子就是"无人机实时 VLA 控制的延迟问题"。三者都不算融合空白——融合空白的原例是"VLM 场景理解 + 世界模型预测 → 无人机规划"，这三个方向没有走这个组合。

4. 基线至少 2 个：未压缩的 OpenVLA 或 OpenVLA-UAV，再加一个有代表性的非 VLA 轻量控制基线；数据集优先用公开基准（如 UAVBench、AeroVerse），若改用 UAV-Flow 的真实与仿真轨迹需说明必要性；指标取成功率、推理延迟和泛化能力，其中延迟是方向 C 的核心（目标 50Hz）。消融要把知识蒸馏与量化分开验证，并做多次运行取均值和标准差。清单没有覆盖、你要自己补的一项：延迟必须在指定的硬件与推理框架（如 TensorRT）上测量并写明配置，否则 50Hz 的主张无法与他人对比。

5. 意味着这类题目做完之后可能没有公认的对照，而 Step 5 的清单要求"至少 2 个有代表性的基线方法"和"使用公开基准（如 UAVBench、AeroVerse）"。所以选题时应优先挑能挂到已有公开基准上的方向——方向 A 可以挂在 GeoChat/UAVBench 上，评测成本低，结果也更容易被承认；像方向 C 那样必须自建 sim-to-real 协议的，即使方法有效，说服力也更依赖自证。反过来看，评估空白本身就是一类可做的贡献，只是那属于基准类工作，投入产出比和方法类不一样。
