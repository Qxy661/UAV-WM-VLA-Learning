    VLM 专题自测与考察¶

    预计阅读：35 分钟 | 前置知识：本专题 01-遥感VLM 起全 7 篇

    本篇是考察篇：正文四层只给指针、不给答案，答案都在七篇原文里。末尾 §7 思考题 是唯一带参考答案的部分，三道都是跨篇综合题，单翻一篇答不出来。

    1. 这一篇怎么用¶

    通用面经问 VLM，答案大多停在连接器怎么接、token 数怎么压、图文对齐怎么训。本专题要考察的多一层：同一道通用题，在遥感与机载上要加两条约束——数据域窄、算力预算硬。本卷前四篇全在应用侧，05–07 三篇补的是通用方法主干，所以每一道通用题在这里都有两个答案——通版的和机载版的。这一篇分三层加一个专场：

    层 考什么 判对的标准 答不上来怎么办
    第一层 知识体系自测 本专题七篇有没有洞 能顺着指针说出那一节的结论与数字 回读指针指向的那一节
    第二层 多模态高频考察点 外部题库问的通用题，本仓库用遥感与机载的口径答 能说出两个版本答案的差别，以及机载版多出的约束 见第二层每条末尾的指针
    第三层 前沿修正 背下来的答案有没有被量反 能说出该说法在什么条件下不成立，以及是哪个实验量出来的 见第三层
    附 无人机专场 别处问不到的 能给出数字，或明确说"本专题没有这条" 见 §5

    这一篇不给答案，只给指针。 答案已经在七篇正文里，再抄一遍的结果是你不会回去读原文；而指针指向的是原文里带实测数字、带出处、带边界条件的那一段。

    本卷现有六节动手验证，分布在五篇里：第 04 篇两节（code/n_quant_bits.py 与 code/o_budget.py），第 02 篇（code/g_eval_metrics.py）、第 03 篇（code/f_control_loop.py）、第 05 篇（code/w_token_budget.py）、第 07 篇（code/x_hallucination_metric.py）各一节。第 01 篇与第 06 篇没有实测段——前者是遥感 VLM 的模型盘点，后者是指令微调与对齐（本仓 8 GB 显存下量不出可信数字，正文已明说）。第三层的判据大多能落到这六段实测上。

    自测方式是遮住指针，每题答出声，再顺着指针核对。答得出大意但说不出数字，按答不上来算。

    末尾 §7 思考题 是唯一带参考答案的一节，三道题都要求把几篇合起来才答得出。它考的不是记忆，是这一卷能不能被当成一个整体用。

    指针里的短名对照：01 遥感VLM · 02 无人机场景理解 · 03 LLM驱动的无人机Agent · 04 边缘VLM部署 · 05 通用VLM架构与视觉编码器 · 06 VLM指令微调与对齐 · 07 通用VLM评测与幻觉。

    判据：判"答对"的标准不是复述术语，而是说出该结论的边界条件与一个具体数字。说不出的那一条，指针就是你的复习清单。

    2. 第一层：知识体系自测¶

    2.1 记忆层¶

    能立刻报出名字、年份、量级，不查资料。

    M1 GeoChat 的基座是什么、参数多少、用了多少条指令数据？ → 01 §3.1

    M2 第 01 篇详讲的五个遥感 VLM 分别是哪几个？各自的参数规模与训练数据规模各是多少？ → 01 §3、§4.2、§4.3

    M3 EarthGPT 提出的多传感器基准叫什么？它分几类子任务、各多少条？ → 01 §3.4

    M4 UAVBench-Test 有几个测试单元、多少样本？UAVIT-1M 的指令-响应对有多少条？ → 02 §3.1

    M5 UAVIT-1M 的五类数据构成各占多少比例？ → 02 §3.3

    M6 BEDI 的六个维度是什么？每个维度的样本量与难度档各是多少？ → 02 §4.3

    M7 四个无人机基准的规模各是多少？各自对应哪篇论文？ → 02 §2、§7.1、§9

    M8 对话式无人机控制那篇测了哪四个 LLM 家族？各自的准确率与延迟是多少？ → 03 §2.3

    M9 Edge-Optimized BLIP-2 在冻结的 BLIP-2 外面挂了哪两个检测器？它自己报的峰值显存是多少？ → 04 §4.1

    M10 量化位宽与精度的那张折算表，FP32 / FP16 / INT8 / INT4 四行的体积、加速比、精度保持各是多少？ → 04 §3.2

    判据：这一层的题只有一个答案，答错说明那一节没读或读串了篇。十题里错两题以上，先回读再往下。

    2.2 机制层¶

    能说出"为什么这样设计"，以及这个设计在什么条件下失效。

    J1 遥感图像的语言歧义从哪来？把"图像级描述"升级成"区域级 grounding"解决了什么？ → 01 §1、§5

    J2 Q-Former 与 32 个 query token 的作用是什么？token 数压下来会先丢哪一类信息？ → 01 §3.2、§4.2

    J3 遥感指令数据为什么靠强模型自动构建？这样做的偏差风险是什么？ → 01 §5.3

    J4 通用视觉基准为什么评不了无人机场景？四条特殊性分别指向哪一类任务失败？ → 02 §1

    J5 "规划能力"与"指令遵循"为什么被设成困难档？六维里哪几维是开环就能测的？ → 02 §4.3

    J6 闭环评测与开环评测差在哪？为什么大多数无人机 VLM 工作停在开环？ → 02 §5、§8.1

    J7 LLM 在无人机系统里可以扮演哪四种角色？三种系统集成模式各把 LLM 放在回路的哪一环？ → 03 §3.1、§3.2

    J8 LLM 迟到时谁来兜底？航点式与连续轨迹式两条链路的失效方式有什么不同？ → 03 §6.2、§6.3

    J9 量化为什么不是一个固定折扣率？离群通道与逐张量 scale 的关系是什么？ → 04 §9.2

    J10 为什么"压延迟"和"压内存"是两件不同的事？各自动哪一侧？ → 04 §10.2

    判据：能说出机制但说不出成立条件，等于背了结论没读判据。这一层每题都对应原文里的一段实测或一条限定。

    2.3 选型层¶

    给一个任务，选出方案并认领代价。这一层没有唯一答案。

    X1 遥感任务该选哪一篇的模型：按参数量选还是按能力矩阵选？ → 01 §4.1、§4.2

    X2 要给一个无人机 VLM 报数，选哪个基准？选错基准会漏掉哪一类能力？ → 02 §7.1、§7.2

    X3 飞控链路里 LLM 放哪个位置？外环周期取多少是可以接受的？ → 03 §3.2、§6.2

    X4 目标平台是 8 GB 显存的机载计算，压缩走哪条路？三条路的倍数范围各是多少？ → 04 §6.2

    X5 量化时选逐张量还是逐通道？同一个位宽下两者的代价差多少？ → 04 §9.2，可对跑 code/n_quant_bits.py

    X6 遇到延迟瓶颈和内存瓶颈，分别在哪一步解决？这两笔账的归属为什么不同？ → 04 §10，可对跑 code/o_budget.py

    判据：选型层没有唯一答案，只有"选了之后要不要认领代价"。答不出代价，说明这个选择还没真正想过。

    3. 第二层：多模态高频考察点¶

    外部题库里有几类题，本专题没有对应内容。这属于范围外，不属于缺口，改了范围才会补：

    • 通用榜单的名次追踪（MMMU / MMBench 上谁排第一）：本卷不追这一层。榜单的口径偏差与幻觉评测的构造已由 04-VLM专题/07-通用VLM评测与幻觉.md 讲清；名次随版本更迭，不进本卷。
    • 训练一个大 VLM 的预训练工程（数据清洗流水线、并行策略、千卡级训练）：本仓库的环境是 8 GB 显存，这一档不在范围内。本卷做的是部署侧的推理与压缩实验。
    • 视觉编码器的自监督预训练（MAE、CLIP 的训练细节）：编码器在本卷里是给定件，被替换而不是被训练。

    4. 第三层：前沿修正¶

    这一层是本仓库唯一没有外部来源的部分。做法是：把外部题库与公开文档里那些到 2026 年已经被量反或限定了适用范围的说法挑出来，给出量它的那一段实测和它的成立条件。背下来就过期的，正是这些。

    4.1 "量化是固定折扣：INT8 保持 97-99%，INT4 保持 93-97%"¶

    本卷自己量过的那一笔把这张表拆了。在能量出小退化的任务上，INT8 这一档 10 颗种子给出的退化从 −9.1% 摆到 +56.4%，区间跨过 0；INT6 同样跨过 0。也就是说"INT8 几乎无损"和"INT8 退化一半"都能从这簇实验里挑出证据。对照组是先看基准自身的波动：FP32 每次都换一颗种子重训，相互之间就差 93%。往下一档从 INT4 起 10 颗种子全部同号，最乐观的一颗也涨了 23.5%。能确定的是断崖存在，不是打折的倍数。 → 04 §9.2、code/n_quant_bits.py

    4.2 "同一个位宽，压缩代价是固定的"¶

    同一个 INT8，逐张量给 scale 与逐通道给 scale，代价可以差近 50 倍。机制在离群通道上：256 个输出通道里有 3 个的量级是其余的 40 倍，全张量共用一个 scale 时分辨率被这 3 个通道吃光，它们自己只差 0.8%，其余 253 个通道却差 33.5%；INT4 更是 100%，即普通通道的权重被整体舍入到 0。这条错误不表现为整体精度下降，而表现为其中一侧静默失效——把视觉编码器与语言模型塞进同一套量化配置就会这样。 → 04 §9.2

    4.3 "压缩一次，延迟和内存一起省"¶

    这是两笔账，量纲和归属都不同。权重那一截是模型的属性——按位宽比精确可算（BLIP-2 的 ViT-g + FlanT5-XL 共 4.1B 参数，fp16 是 7.6 GB，INT8 是 3.8 GB，INT4 是 1.9 GB，一步除法，不含任何假设）。剩下那一截是运行时与任务规模的属性——同一篇论文在离散 GPU 上量到的峰值是约 17 GB，权重按 fp16 只有 7.6 GB，多出来的约 9 GB 是激活、KV cache 和框架开销，这一块换板子也带不走，只能动序列长度和 batch。而唯一能靠"换硬件"改变的延迟，本卷三篇论文一条端侧数字都没有。所以「压缩一次两个一起省」的错处不在于省的幅度，而在于把两笔不同归属的账并成了一笔。 → 04 §10、code/o_budget.py

    4.4 "LLM 的延迟瓶颈是"无法满足实时控制需求""¶

    这个说法两头都不实。一头是出处：本卷所引论文没有一篇测过端到端延迟，Taking Flight with Dialogue 的作者反而把它写进局限（原句："The current evaluation also lacks a quantitative analysis of several vital system metrics, including end-to-end latency, token usage of the language model, and path optimality"）。另一头是量级：仓库自己的仿真把「外环航点刷新周期」这一环换成了数——τ 从 0 扫到 4 秒，跟踪 RMSE 依次是 1.09 / 1.85 / 2.52 / 3.15 m；τ=4 秒对应 3.15 m，已超过机身尺度。但更要紧的是 τ=0 那一行：外环每一步都更新，误差仍有 1.09 m——这部分与延迟无关，是定点悬停的固有代价。这个仿真量的是「规划周期」，不是 LLM 的推理耗时；推理耗时叠加上去只会更长。 → 03 §6.2、code/f_control_loop.py

    4.5 "通用 VLM 的评测结论可以直接搬到无人机场景"¶

    跨形态对照给出的是反例：无人机在所有维度上的表现均低于车辆和机械臂（空间理解 71.4% 对 78.2% 与 82.6%，运动规划 68.9% 对 83.7% 与 79.4%）。归因的三条都指向同一类差别：3D 运动空间更复杂、视角更特殊、动态稳定性更难维持。所以"通用榜单上够用的模型"在无人机上不一定够用。 → 02 §5.4

    4.6 "无人机 VLM 的短板是识别能力不够"¶

    短板不在识别侧。同一份基准里四行模型各自的最弱项落在距离估计（51.2%）、空间推理（42.1%）与运动预测（45.3%）上，最强项则是场景分类（89.1%）、目标检测（81.3%）、描述（76.4%）与问答（83.2%）；综合各基准，空间推理类任务的准确率普遍低于 60%。而无人机应用的核心需求是导航、避障、跟踪，恰好全落在最弱的那两列上。要补的是"量得准、动得对"，不是"看得懂"。 → 02 §3.5、§8.1

    4.7 "两张对比表的数字可以混着引"¶

    第 01 篇自己标了一处口径差：同一批模型在两份文档里的 LLaVA-1.5 对照数字不同，描述任务那一列两边都是 62.1，说明用的是同一个基准；而问答那一列一个是 61.3、一个是 52.3，说明不是同一套评测。所以引用时必须连同表的出处一起引，否则比较的基准在对齐之前就已经错了。 → 01 §3.1

    4.8 "压缩的收益可以用参数量衡量"¶

    参数量只说明了一侧，而且是唯一能先验精确算出来的那一侧。BLIP-2 的 ViT-g + FlanT5-XL 配置共 4.1B 参数，权重按 fp16 是 7.6 GB、INT8 是 3.8 GB、INT4 是 1.9 GB——一步除法，不含假设。但同一篇论文在离散 GPU 上量到的峰值是约 17 GB，多出来的约 9 GB 是激活、KV cache 与框架开销，这一块不随权重精度线性下降，也不随换板子缩小；而真正决定「能不能实时」的延迟，本卷三篇论文一条端侧数字都没有。所以参数量能答的是「权重放不放得进去」，答不了「跑不跑得动」。 → 04 §4.1、§10

    4.9 "闭环评测与开环评测只是流程差别"¶

    差别在能测出什么。综合四家基准的结论，当前 VLM 在无人机场景上的系统性短板有四项，其中第四项是闭环控制能力缺失：大多数 VLM 仅支持开环评测，缺乏与环境的实时交互。前两项（空间推理不足、时序理解薄弱）在开环下还能测出个大概，第四项在开环下根本测不到。 → 02 §8.1

    判据：这一层的用法是给每个结论配一句"在什么条件下成立"。说不出条件的结论，在 2026 年的文献里已经不能当结论用。

    7. 思考题¶

    题目 1：第 04 篇 §9 说"能确定的是断崖存在，不是打折的倍数"，第 03 篇 §6.2 标了"单次实验，固定种子"。这两条限定放在一起，能看出本仓库对"证据强度"的什么规矩？

    一条说某个数在这个规模上量不出来，一条说某个数只来自一次实验。它们是在推卸结论，还是在说别的事？

    参考答案 **两条说的都不是"结论不可信"，而是"结论的粒度不能超过装置的粒度"。** §9 有 10 颗种子，所以它有资格报区间；报不了的是那个用一位小数写成的折扣率，因为区间跨过 0。§6.2 只有一组固定种子的数，所以它能报的是"这条曲线随 τ 单调上升"这种形状结论，报不了"τ=1 秒会偏 1.85 m"这种点值。 **由此得到三条可操作的规矩。** 第一条，先报能不能分辨，再报数值：种子数、区间是否跨过 0、对照组的自身波动（§9 那个 93% 就是对照组）。第二条，"量不出来"本身是个结论，要写成结论而不是写成"没发现差异"——前者的意思是仪器不够，后者的意思是效应可能为零。第三条，限定要写在数字旁边，不能写在文末的免责里，否则引用的人只会拿走数字。 **为什么这条对第三层尤其关键。** [§4](#4-第三层前沿修正) 的每一条都是在反驳一个"写得很确定的数"，反驳的力量全部来自限定写得够干净。没有这套规矩，第三层就只能写成观点对观点。 **结论：** 一个数字的可信度不由它的大小数位决定，由它的装置决定。报告时先说装置，再说数字。

    题目 2：第 02 篇 §3.5 说最强的是场景分类（89.1%）与目标检测（81.3%），最弱的是距离估计（51.2%）；§5.4 说无人机在所有维度低于车辆和机械臂；§8.1 说短板是空间推理与时序理解。三条合起来，为什么"把识别能力再提高一档"不是改善无人机 VLM 的正确杠杆？

    三条来自同一篇的不同节，各自看只是三条观察。它们指向的是同一件事吗？

    参考答案 **三条指向的是同一个错配：模型强在"是什么"，无人机用得到的是"在哪里、往哪去"。** 分类与检测属于前者，已经到 81% 到 89%；距离估计与运动预测属于后者，还在 51% 以下。而无人机应用的核心需求是导航、避障、跟踪，三项全部落在后者。 **跨形态那道对照把这条错配从"领域内的事"提升成了"任务类型的事"。** 无人机垫底的三个维度里，只有"空间理解"是感知量，"运动规划"和"指令遵循"都是决策量；归因的三条（3D 运动空间、视角特殊性、动态稳定性）说的也都是决策与运动，不是识别。 **所以杠杆在哪里。** 提高识别能力是在已经过 80% 的那一列上加分，边际收益低；补空间与时序这一列，动的是闭环评测能不能做起来的前提（§8.1 的第四项短板就是闭环能力缺失）。两件事的成本也不同：前者靠更多标注数据，后者靠带几何与时序真值的评测集与闭环环境——这正是 §8.2 在讲的方向。 **结论：** 判断题要用"哪一环卡住整条链路"，不是"哪一项分数最低"。识别那一列分数已经不低，卡住链路的是空间与时序。

    题目 3：本卷七篇里五篇带实测（第 02 篇一段、第 03 篇一段、第 04 篇两段、第 05 篇一段、第 07 篇一段），第 01 篇与第 06 篇没有。这两篇的结论凭什么可信？

    请把它们各自产出的结论分个类：哪些是量出来的、哪些是核出来的、哪些只是转述的，并各举一例。

    参考答案 **量出来的有六处，分布在五篇里。** 判据是装置与数字都在同一篇里：换一列指标换一套名次（[02 §10.2](../04-VLM专题/02-无人机场景理解.md)）、τ 扫描的 1.09 / 1.85 / 2.52 / 3.15 m（[03 §6.2](../04-VLM专题/03-LLM驱动的无人机Agent.md)）、位宽与退化那簇带 10 颗种子区间的数（[04 §9.2](../04-VLM专题/04-边缘VLM部署.md)）、两个倍差 20.2 与 1.20（[04 §10.2](../04-VLM专题/04-边缘VLM部署.md)）、计数正确率在所有 token 预算下恒为 1.0000 而质心误差涨 8 倍（[05 §9.2](../04-VLM专题/05-通用VLM架构与视觉编码器.md)）、负样本换一档就换一套名次（[07 §9.2](../04-VLM专题/07-通用VLM评测与幻觉.md)）。这一类可以当判据用。 **核出来的是第 01 篇那一处口径提示**（[01 §3.1](../04-VLM专题/01-遥感VLM.md)）：两份文档里 LLaVA-1.5 的描述任务数字都是 62.1，问答那一列却是 61.3 与 52.3。它没有产生新数字，产生的是**引用纪律**——它把"这两张表能不能混着引"这件事从习惯变成了可核对的对象。第 02 篇的能力覆盖矩阵与规模对齐（[02 §7](../04-VLM专题/02-无人机场景理解.md)）属于同一类：产出的是可比性判断。 **第 06 篇是第三种情况：没有装置，且正文自己声明不作为结论**（[06 开篇](../04-VLM专题/06-VLM指令微调与对齐.md)）。指令数据构造、LoRA 秩的边界、灾难性遗忘要量出可信数字必须真训一个 VLM 并做多次消融，本仓的 CPU-only 与 8 GB 条件做不到，所以那一篇所有定量说法一律标「引用」而非「实测」。它产出的是**条件差别**——同一条说法在什么设置下成立、在什么设置下反过来，这一类比转述多一层，但仍不能当判据。 **其余的是转述。** 第 01、02 篇里的模型榜、基准规模、跨形态百分比，来源都是原论文与各基准的报告，本仓库只做搬运与对齐，不改写也不复测。这一类的可信度由出处决定，所以引用时必须带出处——这也是为什么第 01 篇专门标了那条口径提示。 **结论：** 三类结论的用法不同：量出来的可以当判据，核出来的可以当纪律，转述的只能带出处引。**没有装置又没有核对对象的段落，只能当导读，不能当依据。**
