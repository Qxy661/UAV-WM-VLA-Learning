# 知识点注册表（KP Registry）

> 唯一真源。正文、导航、索引都应指向这里，不各写一份。
> 校验：`python tools/kp.py check`；候选抽取：`python tools/kp.py derive`。

## 为什么需要它

审计发现：全库 60 篇正文里「知识点」一词出现 0 次；每篇只有「预计阅读 / 前置知识」两个字段；
9 个专题卷之间没有一条机器可校验的依赖关系。结果是**单篇 A−、跨篇 C**：每篇单独看得懂，
但"我读到第几篇算入门""这个结论依赖哪条前置"只能靠读者自己拼。

注册表把这件事变成数据结构：一条 KP = 一个最小可检验单元，带前置、判据、承载文档、承载代码。
有了它，三件事才可能自动做：导航排序、覆盖检查、论文→知识点→代码的回流。

## 字段

| 字段 | 含义 | 约束 |
|---|---|---|
| ID | 全局唯一编号 | `KP-001`（卷内知识点）/ `KP-X01`（横切判据） |
| 标题 | 一句话说清这个单元 | 不超过 30 字，用名词短语 |
| 层 | 概念 / 机制 / 工程 / 判据 / 能力 | 五选一 |
| 卷 | 主要归属卷 | 与 `docs/` 顶层目录同名 |
| 承载文档 | 讲清它的文档路径；可多篇 | 必须真实存在，未写的写 `待建/…` |
| 前置 | 必须先掌握的 KP | 只能指向已存在的 KP，且不许成环 |
| 判据 | 学完能做什么，越可检验越好 | **不得为空**：没有判据的知识点只是话题 |
| 代码 | 能验证它的 demo 或 `projects/` 模块 | 没有写 `-`，但不许写假路径 |
| 状态 | 完整 / 待补 / 待建 / 争议 | 四选一 |
